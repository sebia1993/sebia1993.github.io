ICMP-01 · Echo Request / Echo Reply PASS

111-byte Echo 5회를 대조했습니다. Request는 Type 8 Code 0, Reply는 Type 0 Code 0이며 Identifier 1 / Sequence 0~4와 Payload가 대응했습니다. CLI도 5/5 성공했습니다.

CP1 Request 47/49/51/53/55 · Reply 48/50/52/54/56 · CP2 Request 13/15/17/19/21 · Reply 14/16/18/20/22

ICMP-02 · TTL Decrement PASS

동일한 5개 Echo Request의 TTL이 CP1에서 255, R2를 지난 CP2에서 254로 관찰됐습니다. Packet 대응은 IP ID, ICMP ID/Sequence와 정규화한 IP Datagram 해시로 확인했습니다.

CP1 47/49/51/53/55 → CP2 13/15/17/19/21 · TTL 255 → 254

ICMP-03 · TTL Expiry / Time Exceeded PASS

TTL=1 UDP Probe가 R2에서 만료됐고 R3 방향으로 Forward되지 않았습니다. R2는 Source로 ICMP Type 11 Code 0을 반환했으며 Error Payload의 quoted IP/UDP header로 원래 Probe를 식별했습니다.

CP1 Probe 59 · R2 Time Exceeded 60 · CP2 동일 Probe 0개 + positive control 확인

ICMP-04 · Cisco IOS Traceroute PASS

첫 UDP Probe는 TTL 1 / destination port 33434, 다음 Probe는 TTL 2 / 33435였습니다. R2는 Type 11 Code 0, R3는 Type 3 Code 3(Port Unreachable)을 반환했고 CLI는 2 Hop에서 종료했습니다.

CP1 59/61 UDP Probes · 60/62 ICMP Errors · CLI: 1 10.10.12.2 → 2 10.10.23.2

ICMP-05 · No Route / Destination Unreachable ORIGINAL FAIL

R2의 목적지 /32 Static Route만 제거하고 Default Route가 없는 것을 확인했습니다. Echo Request는 R2까지 도달했지만 CP2로 전달되지 않았고, 실제 Cisco 응답은 요청서의 Code 0이 아니라 Type 3 Code 1 · Host Unreachable이었습니다. Route 복구 뒤 Ping 5/5와 Traceroute가 정상화됐습니다.

CP1 Echo 105/107/108 · Type 3 Code 1: 106/109 · CP2 downstream Echo 0개 + failure positive control

RESOLVED IMPLEMENTATION DIFFERENCE

RFC 표준 기대와 Cisco IOS 구현을 구분합니다.

RFC 1812: Router에 목적지 Route와 Default Route가 전혀 없으면 Destination Unreachable Code 0(Network Unreachable)을 요구합니다.

Cisco IOS / IOS XE 문서와 이번 Run: 목적지 Route를 모르는 경우 ICMP Host Unreachable(Code 1)을 Source로 보낼 수 있음을 문서화하고 실제로 관찰했습니다.

학습 반영: 원래 ICMP-05 FAIL은 PASS로 바꾸지 않습니다. 대신 “Type 3 Code 하나만 보고 원인을 확정하지 말고 ICMP 생성 Router의 Routing Table과 실제 Forwarding 지점을 함께 확인한다”는 표준/구현 구분으로 해결합니다.
