ETHMAC-01 · Source MAC Learning PASS

PC1 Dynamic FDB Entry를 삭제한 뒤 PC1이 Broadcast ARP Request를 보내자, 실제 PC1 Source MAC 00:50:79:66:68:27이 VLAN 10 / Et0/0에 DYNAMIC으로 학습됐습니다.

CP1 frames 142 / 144 / 145 · SW1 FDB Before/After CLI

ETHMAC-02 · Known Unicast PASS

PC1과 PC2의 FDB 학습 후 PC1→PC2 Echo Request 3개가 CP1과 CP2에서 동일 Ethernet Frame으로 확인됐고 CP3에서는 관찰되지 않았습니다. Destination MAC은 실제 PC2 MAC이었습니다.

CP1 195/198/200 · CP2 153/157/159 · CP3 0 · Destination 00:50:79:66:68:28

ETHMAC-03 · Unknown Unicast Flooding PASS

PC1 ARP Cache는 PC2 MAC을 유지한 채 SW1의 PC2 FDB Entry만 삭제했습니다. 첫 Echo Request는 PC2의 Unicast Destination MAC을 그대로 유지하면서 CP2와 CP3 양쪽에서 관찰됐고, PC2의 Reply 이후 재학습되어 후속 요청은 Known Unicast가 됐습니다.

First request: CP1 230 · CP2 184 · CP3 162

ETHMAC-04 · Ethernet Broadcast PASS

미사용 주소 192.0.2.201에 대한 ARP Request의 Ethernet Destination이 ff:ff:ff:ff:ff:ff임을 확인했고, 동일 Frame이 CP2와 CP3로 전달됐습니다.

CP1 142/144/145 · CP2 105/107/108 · CP3 84/86/87

ETHMAC-05 · Dynamic FDB Aging / Re-learning PASS

검증 장비의 기존 Aging 300초를 기록한 뒤 30초로 설정했습니다. PC2 Entry가 자연 Aging으로 제거된 뒤 첫 Unicast가 Flooding됐고, PC2 Reply의 Source MAC으로 Et0/1에 재학습됐습니다. 시험 종료 후 Aging을 300초로 복구하고 정상 통신까지 다시 확인했습니다.

중요: 이 Run에서 300초였다는 사실을 모든 Switch의 보편적 고정값으로 일반화하지 않습니다.

ETHMAC-06 · ARP Cache와 FDB의 독립 상태 PASS

PC1은 192.0.2.20 → 00:50:79:66:68:28 ARP Mapping을 유지했지만 SW1에는 PC2 FDB Entry가 없는 상태를 재현했습니다. 새 ARP Request 없이 생성된 Unicast Frame이 Switch에서 Unknown Unicast로 Flooding됐습니다.
