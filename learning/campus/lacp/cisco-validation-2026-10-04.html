LACP-01 · Active/Passive Bundle PASS

SW1 active / SW2 passive에서 두 Switch 모두 Po1(SU), M1(P), M2(P)였고 CP1/CP2에서 Actor/Partner System ID와 Key가 일치하는 LACPDU가 관찰됐습니다. End-to-End Host Pair는 정상 통신했습니다.

LACP-02 · Passive/Passive PASS

Clean Rebuild 후 양쪽을 passive로 두자 정상 Bundle이 형성되지 않았고 안정 관찰 구간에서 정상 LACPDU 협상도 시작되지 않았습니다. SW1만 active로 바꾸자 M1/M2가 다시 Bundled되고 Po1 Up / Remote Ping이 복구됐습니다.

Original trial1의 nonegotiate 불일치 구성 오류는 별도 보존하고 formal adjudication에서 제외

LACP-03 · One Logical Link PASS

Bundle 복구 후 STP는 M1/M2를 두 독립 포트로 표시하지 않고 Po1 하나를 Forwarding Link로 표시했습니다. Remote Dynamic MAC도 Po1 기준으로 학습됐습니다.

LACP-04 · Flow-Based Hash Selection PASS after revalidation

Original run01: src-dst-ip에서 F1~F8 모든 Forward Flow가 M1을 사용했습니다. Same-Flow Consistency는 보였지만 다른 Member 분산을 입증하지 못해 INCONCLUSIVE였습니다.

Revalidation run02: src-mac을 양쪽 Switch에 적용하고 실제 PCAP으로 확인했습니다. PC1A→PC2A 5/5 Request는 M2, PC1B→PC2A 5/5 Request는 M1에만 나타났고 Duplicate Request는 없었습니다.

LACP-05 · One Member Failure / Recovery PASS after revalidation

Original run01: SW1의 M1만 shutdown했을 때 Forward Request는 M2로 이동했지만 Return Path가 shutdown M1 Wire에 남아 43/100 Reply 후 추가 0/100이었습니다. 원래 Result는 FAIL로 보존합니다.

Revalidation run02: 신뢰 가능한 PNET live carrier-down API를 확보하지 못해 요청서 fallback대로 M1 양쪽 Endpoint를 하나의 장애 사건으로 admin-down했습니다. M2는 Bundled, Po1은 Up을 유지했고 Core src-mac Run과 원래 src-dst-ip 비교 Run 모두 100 Request / 100 Delivery / 100 Reply / Loss 0을 확인했습니다.

Core의 마지막 M1 Request와 첫 M2 Request 사이 관찰 간격은 약 1.001초, 비교 Run은 약 0.702초였습니다. Probe 간격을 포함한 Packet Observation 값이며 보편적인 LACP Convergence Time으로 일반화하지 않습니다.

LACP-06 · All Members Failure / Recovery PASS

원본 Run에서 M1/M2 모두 Down되자 Po1도 Down됐고 Remote Ping은 실패했습니다. Source Stimulus와 Destination 부재, Local Positive Control을 함께 사용해 판정했습니다. 두 Member를 복구하자 M1(P), M2(P), Po1(SU), Remote Ping 3/3과 Baseline Config가 모두 복구됐습니다.

VALIDATION RESOLUTION

원본 실패를 지우지 않고 재검증으로 해결했습니다.

최종 Teaching Claim은 다음으로 제한합니다. 호환 LACP Bundle은 하나의 Logical Link이며, 검증된 src-mac 입력의 서로 다른 Flow는 서로 다른 Member를 선택했습니다. 한 Member가 양단에서 unavailable이고 다른 Member가 Bundled라면 이 IOL Run에서는 남은 Member로 양방향 통신을 유지했습니다.

주장하지 않는 것: 모든 Hash Method에서 같은 분산, 50:50, 단일 Flow 처리량 2배, Universal Zero-Loss, Universal Convergence Time, 실제 Cable Carrier Propagation의 내부 구현 원인.
