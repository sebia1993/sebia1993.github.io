IVR-01 · Same-VLAN Direct L2 PASS

PC10A는 PC10B 10.10.10.20을 직접 ARP했고 Echo Request Ethernet Destination도 PC10B MAC이었습니다. CP1/CP3에서 같은 Request의 TTL은 64로 동일해 SVI Routing이 개입하지 않았습니다.

ARP target 10.10.10.20 · CP1/55 ↔ CP3/48 · TTL 64 → 64

IVR-02 · Off-Link Uses Default Gateway PASS

PC10A→PC20A에서는 PC10A가 10.10.10.1을 ARP했습니다. Ingress Echo Ethernet Destination은 Vlan10 SVI MAC이지만 IPv4 Destination은 최종 PC20A 10.10.20.10 그대로였습니다.

CP1 ARP frame 71 · Gateway MAC aa:bb:cc:80:01:00 · Remote Host 직접 ARP 없음

IVR-03 · SVI Routing / TTL / Re-encapsulation PASS

동일 Echo Request가 CP1에서 TTL 64, CP2에서 TTL 63으로 확인됐습니다. IP Source/Destination은 그대로였고 Ethernet은 PC10A→SVI에서 SVI→PC20A로 바뀌었습니다.

CP1/73: 10.10.10.10→10.10.20.10 TTL64, PC10A→SVI · CP2/63: same IP TTL63, SVI→PC20A

IVR-04 · Independent Reply Path PASS

PC20A는 PC10A를 off-link로 판단해 Vlan20 Gateway MAC으로 Echo Reply를 보냈습니다. SW1은 VLAN10으로 Routing하면서 TTL 64→63으로 감소시키고 Ethernet Destination을 PC10A MAC으로 구성했습니다.

PC20A ARP: 10.10.20.1 → aa:bb:cc:80:01:00 · Round-trip 3/3

IVR-05 · Vlan20 SVI Down / Recover PASS

Vlan20 shutdown 후 SVI는 down/down, 10.10.20.0/24 Connected Route는 제거됐습니다. Inter-VLAN은 실패했지만 PC20A↔PC20B Same-VLAN L2는 3/3 유지됐습니다. 실제 IOL은 PC10A에 ICMP Type 3 Code 1을 반환했습니다.

no shutdown 직후 첫 Recovery는 2/3이었고, ARP 재형성 후 별도 확인 Run에서 3/3이 됐습니다. 이 transient를 숨기지 않습니다.

Failure CP1 Echo + Type3/Code1 · CP2 Routed Echo 0 · CP2/CP4 VLAN20 L2 Positive Control

IVR-06 · Wrong Default Gateway / Recover PASS

PC10A Gateway만 10.10.10.254로 변경하자 PC10B Same-VLAN은 3/3 유지됐고 Remote-VLAN은 .254 ARP Reply가 없어 중단됐습니다. PC20A를 Destination IP로 하는 실제 Echo Frame은 생성되지 않았습니다.

CP1 wrong-gateway ARP frames 280/282/283 · Remote Echo frames 0 · Gateway .1 복구 후 3/3

검증 한계

이 Lab에는 Trunk가 없습니다.

VLAN / Trunk 자체는 직전 학습에서 이미 검증했기 때문에 이번 Inter-VLAN Lab은 한 L3 Switch의 Access VLAN + SVI 경계만 사용했습니다. 따라서 이 페이지에서 802.1Q Tag가 검증됐다고 주장하지 않습니다.

또한 이번 IOL 이미지에서는 Vlan10과 Vlan20 SVI의 Numeric MAC이 모두 aa:bb:cc:80:01:00이었습니다. 핵심 증거는 SVI MAC 값이 서로 다르다는 것이 아니라, Routing 전후 Egress Destination MAC과 TTL이 올바르게 바뀌는 것입니다.
