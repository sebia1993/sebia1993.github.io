VLAN-01 · Access Port / Access VLAN PASS

PC20A/PC20B Port는 static Access VLAN 20이었고 두 MAC은 VLAN 20에 동적 학습됐습니다. Host-facing CP1/CP3의 정상 ICMP Request/Reply는 모두 802.1Q Header가 없는 Untagged Frame이었습니다.

CP1 #27,28,29,30,32,33 · CP3 #26,27,28,29,31,32

VLAN-02 · Non-native 802.1Q Tag PASS

동일 VLAN 20 Traffic이 CP1 Access에서는 Untagged, CP2 Trunk에서는 VLAN ID 20 Tagged, CP3 Access에서는 다시 Untagged로 관찰됐습니다. MAC/IP/ICMP ID·Sequence와 L3 bytes를 대조했습니다.

CP2 #82,83,84,85,89,90 · VLAN ID 20

VLAN-03 · VLAN Separation PASS

PC20A의 ARP Broadcast는 CP1 → CP2(VLAN20 Tag) → CP3에 나타났고 VLAN10 Access Link인 CP4에는 나타나지 않았습니다. CP4의 별도 VLAN10 ARP/Ping Positive Control은 정상 수집됐습니다.

PC20A ARP: CP1 #25 → CP2 #80 → CP3 #24 · CP4 동일 Broadcast 0

VLAN-04 · Native VLAN 99 Untagged PASS

양쪽 Trunk Native VLAN은 99였고 global native tagging은 disabled였습니다. VLAN 99 Ping은 성공했고 CP2에서 VLAN99 Frame은 Untagged, 같은 Trunk의 VLAN10/20 Traffic은 Tagged였습니다.

CP2 VLAN99 #108,109,113,114,115,116 · Untagged

VLAN-05 · Allowed VLAN Missing / Recover PASS

SW1 Trunk Allowed 목록에서 VLAN20만 제거하자 Port/Trunk는 Up 상태를 유지했지만 PC20A ARP는 CP1까지만 나타나고 CP2/CP3에는 없었습니다. VLAN10/99는 계속 성공했습니다. VLAN20 복구 후 STP Forwarding을 확인한 뒤 통신과 VLAN20 Tagged Frame이 다시 나타났습니다.

Failure CP1 #91,92,94 · Recovery CP2 #542–547 / CP3 #172–177

VLAN-06 · Access VLAN Mismatch / Recover PASS

SW2의 PC20B Port만 Access VLAN10으로 변경하자 VLAN20 ARP는 CP1과 CP2 Trunk까지 정상 도달했지만 CP3에는 나타나지 않았습니다. CP3에서 VLAN10 Positive Control이 수집돼 Capture 경로가 정상임을 확인했습니다. Port를 VLAN20으로 원복한 뒤 통신과 Traffic이 복구됐습니다.

Failure CP1 #256,257,259 · CP2 #765,766,770 · CP3 VLAN20 0 · Recovery CP2 #881–889 / CP3 #279–285

검증 한계

Nexus 9000v 결과로 일반화하지 않습니다.

이번 실제 플랫폼은 요청서가 허용한 Cisco IOL L2 fallback입니다. Nexus 9000v는 직접 실행하지 않았습니다. 또한 Native VLAN의 Wire 형식은 native VLAN tagging 기능에 따라 달라질 수 있어, 최종 학습자료는 “이번 Cisco 기본 설정 / 검증 환경에서 Untagged”라는 조건을 유지합니다.

Allowed VLAN 복원 직후 첫 재시도는 이번 Run에서 STP 전환 중 실패했습니다. Forwarding 확인 후 정상화됐으므로 “설정 한 줄 원복 = 즉시 통신 복구”라고 표현하지 않습니다.
