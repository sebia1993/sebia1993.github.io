DHCP-01 · DORA Establishes a Lease PASS

Baseline Transaction 0x57370148에서 Discover → Offer → Request → ACK를 같은 Client MAC과 xid로 상관시켰습니다. ACK 이후 PC1은 192.0.2.100/24를 사용했고 R2 DHCP Binding에도 Client가 나타났습니다.

DHCP-02 · ACK Lease / Options PASS

Baseline ACK에서 Option 1 255.255.255.0, Option 3 192.0.2.1, Option 6 203.0.113.53, Option 51 3600을 확인했습니다. Client는 Address/Mask/Gateway를 적용했고 R1 및 R2까지 Ping이 정상 동작했습니다.

DHCP-03 · Relay / giaddr PASS

Client Discover는 giaddr 0.0.0.0의 Local Broadcast였고, CP3의 Relayed Discover는 같은 xid/chaddr를 유지하면서 giaddr=192.0.2.1, hops=1이었습니다. R2는 192.0.2.0/24 Pool에서 .100을 제안했습니다.

R1→R2 relayed DHCP: UDP 67→67 · giaddr 192.0.2.1

DHCP-04 · Server Service Down / Recover PASS

R2에 no service dhcp만 적용하자 Client Discover는 CP1/CP2뿐 아니라 CP3 Server Segment까지 도달했지만 Offer/ACK는 없었고 신규 Lease가 실패했습니다. R1↔R2 ICMP Positive Control은 정상입니다. Service 복구 후 신규 DORA와 Remote Ping 3/3이 복구됐습니다.

DHCP-05 · Relay Missing / Recover PASS

R1 Client Interface의 ip helper-address만 제거하자 Discover는 CP1/CP2에 계속 있었지만 CP3에는 해당 xid/chaddr의 Relayed DHCP가 없었습니다. CP3 ICMP Positive Control은 정상이라 Capture Failure가 아니었습니다. Helper 복구 후 신규 DORA와 Remote Ping이 정상화됐습니다.

DHCP-06 · Wrong Router Option / Recover PASS

Pool의 Default Router만 192.0.2.254로 바꾸자 DORA와 Lease 자체는 정상 완료됐습니다. Client는 .254를 Gateway로 적용했고 Remote R2 Ping 시 .254에 대한 ARP만 반복하며 Reply를 받지 못했습니다. Option 3을 .1로 복구하고 신규 DORA 후 Remote Ping 3/3이 복구됐습니다.

핵심: DHCP Address Allocation 성공과 실제 Network Connectivity 성공은 별도 상태입니다.
