별도 WPA2-MFP 표본 · 비교 전용

AKM 6 · MFPC 1 / MFPR 1

  • Beacon 1: RSN 0x00cc
  • Assoc Request 4: RSN 0x00c0
  • Group Management Cipher Type 6: BIP-CMAC-128

PMF 지원·요구 비트의 비교 자료입니다. SAE 세션도, 위조 관리 프레임의 차단 실험도 아닙니다.

서로 다른 표본을 합쳐 SAE + PMF 성공 사례를 만들지 않습니다. 파일 이름이나 “WPA3 지원” 표시만으로 해당 세션의 요구사항을 채우지 않습니다.

미시험과 동결 Expected 보존

Probe 교환, 의도적인 잘못된 암호의 실패·복구, 동일 SAE 세션의 필수 PMF, 사용자 장비의 접속·데이터 성공은 확인하지 않았습니다. 프레임 누락만으로 암호 오류를 확정하지 않습니다.

WLAN-04 원문 표현 차이

WLAN-04의 frozen 입력에는 표현 차이가 있다. Research Brief Expected는 Auth/Assoc 성공 관측을 요구하고, Validation Request는 성공할 수 있다고 기술한다. 두 원문을 보존하며 이번 교육 모델의 조건부 설명은 원래 실측 요구나 판정을 완화·대체하지 않는다. 재시도 횟수는 별도로 구현 의존 사항이다.

두 원문의 Claim 절과 SHA256은 JSON에 보존했습니다. Actual은 null이며 기존 보고서를 바꾸지 않았습니다.

REPRODUCIBLE OFFLINE ANALYSIS

원본과 필드로 다시 확인할 수 있습니다.

  1. 고정 commit의 공식 압축 원본과 압축 해제본을 보존하고 URL·다운로드 UTC·SHA256을 기록했습니다. 프레임 번호 대조 전 해시부터 확인합니다.
  2. TShark 4.6.9에서 -n -r -T fields로 복호화 OFF/ON 결과를 분리했습니다. 캡처 인터페이스나 모니터 모드는 열지 않았습니다. capinfos로 22/18/143프레임과 Radiotap을 확인했습니다.
  3. 복호화는 동일 commit의 공개 시험 키만 프로세스 한정 설정으로 제공했습니다. 사용자 암호를 사용하지 않았고 분석 프로필을 격리했습니다. 안정 버전이 지원하지 않는 무관한 64-byte PMK fixture 항목은 제외했습니다.
  4. 같은 AP/STA·Pairwise Key Type·방향·Replay Counter와 실제 DHCP xid/ICMP ID·Seq를 대조했습니다. Protected bit만으로 데이터 성공을 판단하지 않았습니다.
  5. MAC/SSID/IP는 별칭으로 바꿔 저장했습니다. 별칭 필드 JSON만 공개하며 원본 PCAP과 분석기 바이너리는 원본 링크로 제공합니다.
