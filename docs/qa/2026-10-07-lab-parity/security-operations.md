# 보안·운영 실습 개선 기록

대상: ACL, NAT/PAT, Stateful Firewall/IPsec VPN, Packet/Log/SNMP 관측, Network Automation의 5개 실습 / 28개 원본 문제.

## 학습 페이지 선확인과 이름 대응

2026-10-07 현재 작업 트리의 각 Concept Guide 본문과 선택 자료를 먼저 읽었다. 학습 페이지는 수정하지 않았다. 이름을 바꾸는 것은 표시 계층이며 원본 문제 배열, 정답 키, 기존 근거/CLI/로그는 그대로 유지한다.

| 실습 | 현재 학습 페이지의 장비 대응 | 내용 연결 및 보존 조건 |
|---|---|---|
| ACL | Router A/B/C = R1/R2/R3 | 적용 인터페이스와 방향 → 위에서부터 ACE → 첫 일치 → Permit/Deny. ICMP와 TCP/23을 분리한다. Echo Request만 차단한 수정 실험과 원래 모든 ICMP 차단의 실패 기록을 보존한다. |
| NAT/PAT | Router A/B/C/D = R1/R2/R3/R4 | A와 D는 내부, B는 NAT 경계, C는 외부. 값의 대응 기록 → 외부 전달 → 응답 역변환. 미변환 전달을 보안 Drop으로 표시하지 않는다. 관측된 PAT Port 보존과 .5:2323↔10.0.11.2:23 기록을 유지한다. |
| Firewall/VPN | Router A~E = R1~R5 | inspect/pass와 Session 판단, Selector/SA/ESP를 구분한다. 방화벽 실험과 VPN 실험을 별도 조건으로 명시한다. Router C는 학습 페이지 선택 자료의 경유 Router이자 대조 통신 대상이며 기본 그림보다 상세히 표시하는 이유를 안내한다. |
| 관측 | Router A/B = R1/R2, PC A = NMS1 | A↔B 데이터 링크와 A↔PC A 관리 링크를 구분한다. Ping 결과·Syslog·GET·Trap을 같은 대상과 상태 변화로 연결한다. Trap에 없는 Admin/Oper 값은 GET에서만 확인하며 31.187초는 이 실험의 관측값으로 한정한다. |
| 자동화 | Router A/B/C = R1/R2/R3, PC A = NMS1 | 대상/기준 → 읽기 전용 수집 → 원문 → 정규화 → 비교 → JSON 보고서. 기준 불일치와 수집 오류/비교 미실행을 분리한다. 접속 설정 오류를 Router C 장비 장애로 표현하지 않는다. |

각 화면에 새 이름과 기존 검증 이름의 대응을 명시했다. 원래 이름이 필요한 근거는 원문 영역으로 보존한다.

## 적용 내용

- ARP 공통 CSS와 장비 심볼을 직접 재사용한다. 공통 실행/채점 컨트롤러는 루트 작업과 통합한다.
- 모든 문제에 목적이 드러나는 질문형 제목, 시작 안내, 3단계 힌트를 추가했다.
- 일반 영어 UI는 표시 사전으로 한국어화한다. 원문 데이터 배열과 실제 코드/로그는 번역하지 않는다. Network Automation에서는 `PASS` → 기준 일치, `MISMATCH` → 기준 불일치, `ERROR` → 수집 오류, `NOT_EVALUATED` → 비교 미실행을 구분한다. Firewall의 실제 `pass` / `inspect` 정책 동작은 유지한다.
- ACL은 요청 도착 → 방향/ACE 비교 → 허용/차단 → 다른 프로토콜 또는 역방향 흐름 관찰로 분리했다.
- NAT는 실제 장비 연결을 따른 요청·응답 이동과 동시에 Translation 기록을 단계적으로 보여준다.
- Firewall은 요청·Session·응답을 분리하고 VPN은 원래 ICMP → ESP 경유 → 원래 ICMP 순서로 보여준다. 인증 실패에서는 사용할 SA나 ESP 데이터가 존재하는 것처럼 이동시키지 않는다.
- 관측은 정상·장애·복구 자료 또는 GET/Trap 방향을 별도 관찰 단계로 보여준다. 실제 자료의 시각을 수정하거나 지연 규칙을 새로 만들지 않는다.
- 자동화는 Router별 SSH 수집과 기준 비교를 분리한다. 수집 오류의 실제값을 임의 생성하지 않는다.
- 선택적 비교/복구도 단계별 계획을 사용한다. 복구 버튼을 누르기 전에 복구된 상태로 바꾸지 않는다.

## 재생과 모바일

`security-operations-presentation.js`는 이 5개 실습만 사용하는 표시 보조 모듈이다. ARP의 연결 구간 420ms + 도착 180ms, 판단 1050ms를 재사용한다. 전부 2490ms로 고정하지 않는다. Marker 위치는 컨트롤러가 전달한 진행률과 실제 장비 DOM 좌표로 계산하여 일시정지, 창 크기 변경, 세로 배치에도 경로가 일치하도록 한다. 별도 타이머나 RAF 실행 소유권은 만들지 않는다.

모바일은 같은 장비 DOM을 재배치하여 복제된 상태가 어긋나지 않게 한다. ACL은 세로 경로, NAT는 두 내부 장비와 NAT 경계/외부 장비, Firewall/VPN은 연결 순서를 유지한 접힌 경로, 관측은 데이터/관리 분기, 자동화는 PC A에서 세 장비로의 독립 관리 연결이다. 넓은 고정 SVG의 가로 이동에 의존하지 않는다. 두 관측 실습의 PC A도 ARP PC 심볼로 표시한다.

## CI 캡처 육안 검수와 후속 수정

루트 통합 CI가 생성한 `qa/ci-final/guide-aligned-v2`의 실제 Chromium 캡처를 확인했다. 이 그룹의 360/768/1366/1920px 관찰 영역 20개, 초기/완료 전체 화면 40개를 직접 또는 원본 기반 검수용 모음/크롭으로 확인했다. 모바일에서는 제목·선택지·결과·하단 조작 영역을 원래 크기로 별도 읽었다. 원본 캡처는 변경하지 않았다.

자동 기능 검사 통과와 별개로 다음 화면 결함을 발견하여 수정했다.

| 발견 | 후속 수정 | 재캡처 상태 |
|---|---|---|
| ACL 차단 표시가 큰 세로 타원으로 늘어나 Router B를 가림 | 공유 CSS의 top 값과 그룹 CSS bottom 값이 함께 적용된 원인을 제거하고 표시 높이를 내용에 맞춤 | 통합 재검수 대기 |
| ACL/NAT/Firewall 데스크톱에서 현재 사건이 빈 오른쪽 열을 차지하고 상태 표가 아래로 내려감 | 토폴로지·현재 사건·상태 표에 명시적인 grid area 부여 | 통합 재검수 대기 |
| 모바일 CP 라벨이 장비 이름/주소와 겹침 | 연결 중간점에서 수직 방향 후보 위치를 계산하고 장비 박스 및 그림 경계와 겹치지 않는 위치 선택 | 통합 재검수 대기 |
| 자동화의 중앙 연결선이 PC A 설명을 관통 | 이름과 설명에 토폴로지 배경과 같은 불투명 배경 적용 | 통합 재검수 대기 |
| Animation, action, reverse policy 등 일반 영어 잔존 | 표시 사전을 추가하고 명령어·원본 근거는 보존 | 통합 재검수 대기 |

모바일 고정 문제 탭이 그림을 가리는 현상과 초기 숨긴 상태 패널의 여백은 루트에 공유했다. 해당 공통 계층의 수정과 후속 CI/공개 검사 결과를 통합 보고서에서 기록한다. 이 최초 캡처의 시각 검수는 결함 발견 결과이므로 수정 후 PASS 증거로 재사용하지 않는다.
