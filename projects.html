WLAN · OBSERVABILITY

Aruba Cluster Health Dashboard

문제

Controller 상태, Client 분배, Cluster 결과를 각각 CLI로 확인한 뒤 사람이 다시 대조해야 했습니다.

판단

SSH 실패와 WLC Down을 같은 상태로 보지 않고, 순간 변동은 연속 관측 후 이상으로 확정하도록 상태를 분리했습니다.

내 역할
  • 운영 문제 정의
  • 수집 명령·데이터 정의
  • 정상·주의·장애 판정기준 정의
  • 화면에 보여줄 근거 정의
  • 실제 환경 테스트·검증
운영 가치

장비별 반복 접속과 수동 비교를 줄이고, 여러 관측값을 하나의 상태 화면에서 확인할 수 있게 했습니다.

PACKET · TROUBLESHOOTING

WLAN Troubleshooter KO

문제

캡처에 응답이 보이지 않는다는 이유만으로 RF, ClearPass, DHCP, DNS, Firewall 장애를 자동 확정하면 잘못된 결론을 만들 수 있었습니다.

판단

명시적 실패 패킷만 Finding으로 만들고, 관찰되지 않은 사실은 판단불가로 남기도록 분석 경계를 정했습니다.

내 역할
  • 분석 프로토콜·단계 정의
  • 실패·미관찰·판단불가 구분
  • 비식별 요구사항 정의
  • 결과 표현 구조 정의
  • 테스트·검증
운영 가치

802.11→EAPOL→RADIUS→DHCP→DNS→TCP를 하나의 흐름으로 정리해 초동 장애 범위를 좁히는 근거로 활용할 수 있게 했습니다.

CAMPUS · CHANGE VALIDATION

HPE Comware Change Validator

문제

작업 전후 Interface, LACP, VLAN, STP, OSPF, VRRP 상태를 장비마다 다시 조회하고 직접 비교하는 과정이 반복적이었습니다.

판단

항상 바뀌는 값은 정규화하고, 계획된 변경과 비예상 위험을 분리해 단순 diff를 장애와 동일시하지 않도록 했습니다.

내 역할
  • 수집 명령 정의
  • 비교·위험 판정기준 정의
  • HTML 결과 구조 정의
  • 검증 시나리오 설계
  • 실제 환경 테스트·검증
운영 가치

수작업 비교 시간을 줄이고, 여러 장비의 변경점을 HTML로 한눈에 확인할 수 있게 했습니다.
