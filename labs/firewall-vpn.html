16 · 1단계 CONCEPT GUIDE

Stateful Firewall / IPsec VPN

통신 상태를 보는 방화벽과 구간을 보호하는 VPN의 역할을 구분합니다.

앞선 학습 · NAT / PAT까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

통신을 허용하는 것과 통신 내용을 보호하는 것은 같은 일일까요?

30초 핵심 · Stateful 방화벽은 연결 상태와 정책으로 패킷을 판단합니다. IPsec VPN은 정해진 보호 대상 트래픽을 두 끝점 사이에서 보호합니다. 두 기능은 서로 다른 질문에 답합니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

Stateful / Session
통신의 상태를 기억하며 판단하는 방식과 그 연결 기록입니다.
IPsec / ESP
IP 통신을 보호하는 체계와 보호된 데이터를 운반하는 방식입니다. 이 예제는 사이트 사이 VPN입니다.
Selector / SA
Selector는 보호할 통신의 조건, SA는 사용할 보호 방식·키 등의 합의 상태입니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 방화벽은 새 요청을 정책에 따라 허용하고 필요한 연결 상태를 만듭니다.
  2. 돌아온 패킷이 기존 연결에 맞는지 봅니다.
  3. VPN에서는 통신이 보호 대상인지 별도로 판단합니다.
  4. 보호 상태가 준비되면 VPN 구간에서 보호하고 상대 끝점에서 원래 패킷으로 전달합니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
방화벽의 질문이 패킷을 정책·연결 상태상 통과시켜도 되는가?
VPN의 질문이 통신을 어떤 구간에서 어떤 보호 상태로 보낼 것인가?

05 · 복습

꼭 기억할 세 가지

  • 허용과 암호화는 다른 역할입니다.
  • Stateful 판단에는 기존 통신 상태가 중요합니다.
  • 경로가 있어도 보호 상태가 성립하지 않으면 VPN 통신이 실패할 수 있습니다.

1단계 · CONCEPT GUIDE

Stateful Firewall / IPsec VPN

이번 목표는 하나입니다. Stateful Firewall이 Return Traffic을 허용하는 이유와, Site-to-Site IPsec이 LAN Traffic을 ESP Transit으로 바꾸는 흐름을 한 경로에서 설명할 수 있으면 됩니다.

Route가 정상이어도 Policy·Session·SA 때문에 통신은 실패할 수 있습니다.진단 순서는 Route → Policy → Session → NAT State → VPN SA → ESP Path로 잡습니다.
1 · 개념서2 · Interactive Lab
Stateful Policy: First Flow → Session State → Return Match   |   IPsec: Selector → SA → ESP → Decrypt

공통 핵심은 같은 Route 위에서도 Policy/Session State와 Encryption/SA State가 서로 다른 판단 계층이라는 점입니다.

구현 범위: Firewall의 inspect/pass와 ZBF Zone-Pair는 Cisco IOS Zone-Based Firewall 구현입니다. IPsec의 Selector/SA/ESP Mental Model은 표준 중심으로 보고, 이번 IKEv1/AES/SHA 조합은 Lab 구현 Evidence로만 사용합니다.
00 · 30초 핵심

같은 Route 위에서도 Firewall과 VPN은 서로 다른 State를 봅니다.

STATEFUL FIREWALL

첫 Packet에서 Session 생성

Inside에서 시작한 Flow를 inspect하면 Firewall이 Session을 만들고, Return Packet은 새 연결이 아니라 기존 Session으로 판단합니다.

Route → Policy → Inspect → Session → Return Match
SITE-TO-SITE IPSEC

Selector에 맞는 Traffic만 Protect

보호 대상 LAN Traffic은 VPN Peer 사이에서 ESP로 보이고, Selector 밖의 Traffic은 평문으로 Bypass될 수 있습니다.

Route → Selector → IKE/IPsec SA → ESP → Decrypt

02 · STATEFUL FIREWALL

inspect는 Return Traffic을 위한 Session을 만들고, pass는 만들지 않습니다.

FWVPN-01 · INSPECT

Inside → Outside 연결 성공

R1→R3 TCP/23에서 Session이 생성됐고 reverse zone-pair가 없어도 SYN-ACK이 R1까지 돌아왔습니다.

R1:40889 → R2 inspect/session → R3:23
Return → R2 session match → R1
SIS_OPEN / TCP_ESTAB
FWVPN-02 · UNSOLICITED

Outside 신규 연결은 Stop

R3가 새 TCP Flow를 시작하자 CP23에는 SYN이 있었지만 CP12에는 대응 SYN이 없었고 Session도 생성되지 않았습니다.

R3 SYN → CP23 → R2 STOP
CP12 matching SYN = 0
NO ESTABLISHED SESSION
FWVPN-03 · PASS vs INSPECT

pass는 허용이지만 Stateful Return Permit은 아닙니다.

pass 상태에서는 R1 SYN은 R3까지 갔지만 SYN-ACK은 CP23까지만 돌아왔고 CP12로 가지 못했습니다. inspect로 원복하자 Session이 다시 생성되고 연결이 정상 복구됐습니다.

03 · SITE-TO-SITE IPSEC

보호 대상 LAN Traffic은 Clear → ESP → Clear로 바뀝니다.

CP12 · CLEAR10.10.10.2 → 10.20.20.2 ICMP
→
CP23 / CP34 · ESP192.0.2.1 ↔ 192.0.2.6
→
CP45 · CLEAR10.10.10.2 → 10.20.20.2 ICMP
Actual: Ping 3/3, 양쪽 Peer QM_IDLE, R2/R4 각각 encaps/decaps +3. Transit의 ESP는 SPI/sequence/ciphertext hash로 양쪽 CP를 대응시켰으며 암호문을 복호화했다고 주장하지 않습니다.
FWVPN-04 · PROTECTED

Selector Match → ESP

LAN10.10.10.0/24 ↔ LAN10.20.20.0/24 Traffic은 보호 대상이라 Transit에서 ESP로 관측됐습니다.

LAN-A → R2 encrypt → ESP → R4 decrypt → LAN-B
FWVPN-05 · BYPASS

Selector 밖 Traffic → Clear IP

R1→R3 Control ICMP는 VPN Selector 밖이라 CP23에서 원래 IP Packet으로 보였고 ESP counter는 Protected Flow에 대해서만 증가했습니다.

R1 → R2 bypass selector → CP23 clear ICMP → R3
04 · IKE FAILURE / RECOVERY

인증이 맞지 않으면 Route가 있어도 usable SA가 생기지 않습니다.

FWVPN-06 · FAILURE

PSK mismatch → 0/3

기존 SA를 지운 뒤 한쪽 인증값만 다르게 하자 R2는 MM_KEY_EXCH, R4는 IKMP_BAD_MESSAGE 상태를 보였고 active IPsec SPI와 ESP Data Flow가 없었습니다.

Protected ICMP request → IKE negotiation
No usable IPsec SA → no protected ESP data
ENCAP / DECAP = 0
RECOVERY

인증 원복 → QM_IDLE + ESP

인증값을 다시 맞추고 양쪽 stale state를 정리한 뒤 measured Ping 3/3, QM_IDLE, ESP 및 counters +3이 다시 확인됐습니다.

Matching auth → IKE/IPsec SA → ESP → Ping 3/3
VPN BASELINE RESTORED
05 · REVIEW

⭐ 꼭 기억하세요

  • inspect는 Session을 만들고 Return Traffic을 그 State로 허용합니다.
  • pass는 Packet을 통과시켜도 Stateful Session을 만들지 않습니다.
  • IPsec Selector에 Match한 Traffic은 SA를 통해 ESP로 보호되고, Match하지 않으면 Bypass될 수 있습니다.
  • VPN 장애는 Route → Policy/Selector → Session/NAT → IKE/IPsec SA → ESP Path 순서로 좁힙니다.
