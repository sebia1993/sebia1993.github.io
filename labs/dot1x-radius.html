인증이 성공한 뒤에 VLAN/Role 같은 인가 결과가 적용됩니다. “인증 성공”과 “어느 VLAN/Role을 받았는가”는 다른 질문입니다.

검증 범위: 실제 Lab은 Cisco L2 Switch를 Authenticator로 사용했습니다. Enterprise WLAN에서는 같은 역할 경계에서 AP/Controller가 Authenticator/NAS 역할을 맡습니다. 유선과 무선의 Data-plane enforcement 구현이 동일하다고 가르치지 않습니다.

EAPOL과 RADIUS는 서로 다른 구간에서 같은 EAP 대화를 운반합니다.

DOT1X-01 / 02 ACTUAL

20개의 EAP Packet을 EAPOL ↔ RADIUS로 직접 대응

정상 BLUE 인증에서 EAP 전체 바이트 SHA-256까지 대조해 20개 Relay를 동일 Packet으로 연결했습니다. Supplicant가 RADIUS를 직접 보내는 구조가 아니라 Authenticator가 EAP를 RADIUS에 실어 전달하는 구조가 확인됐습니다.

DOT1X-03 ACTUAL

PEAP/MSCHAPv2 → Access-Accept → Authorized

실제 Method는 PEAPv0/MSCHAPv2 over TLS1.2였습니다. BLUE는 Access-Accept #324, EAP Success, Cisco Authorized, VLAN20, DHCP 10.77.20.10, Ping 3/3까지 일치했습니다.

Nuance: 최초 Request/Identity는 SW1 Authenticator가 로컬로 생성했습니다. 모든 EAP Frame이 RADIUS에서 왔다고 단순화하면 안 됩니다.

04 · TWO FAILURES, DIFFERENT ROOT CAUSES

EAP Failure 한 줄만 보고 “비밀번호 오류”라고 판단하면 안 됩니다.

DOT1X-04 · EXPLICIT REJECT

BAD Credential → Access-Reject

BLUE Identity에 잘못된 Lab Password를 한 번 사용하자 RADIUS Access-Reject #371, EAP Failure, Unauthorized, Ping 0/3이 확인됐습니다.

EAP starts → Access-Reject → EAP Failure → Unauthorized → DATA STOP
명시적 인증 실패
DOT1X-06 · NO RESPONSE

RADIUS Service Down → Retry / Timeout

Lab FreeRADIUS만 중단하자 동일 EAP payload의 Access-Request가 3회 전송됐지만 Access-Accept/Reject는 0개였습니다. Cisco Timeout/Unauthorized와 Ping 0/3이 확인됐습니다.

Access-Request ×3 → no RADIUS reply → timeout → Unauthorized
AAA 서버 응답 실패
중요: RADIUS UDP Port가 닫혀 Linux가 ICMP Type3 Code3을 반환한 Packet도 실제로 있었습니다. 따라서 “IP 응답이 전혀 없었다”가 아니라 “RADIUS 응답이 없었다”가 정확한 표현입니다.

05 · REVIEW

이 다섯 문장을 연결해서 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Supplicant↔Authenticator는 EAPOL, Authenticator↔RADIUS는 RADIUS입니다.
  • Access-Accept는 인증 성공을 뜻하지만 VLAN/Role은 별도의 인가 결과입니다.
  • Access-Reject와 RADIUS 무응답은 다른 장애입니다.
  • EAP Failure만으로 실패 원인을 단정하지 않습니다.
  • 실제 WLAN에서는 AP/Controller가 Authenticator 역할을 맡습니다.
