03 · 1단계 CONCEPT GUIDE

Ethernet / MAC Table

스위치가 출발지 주소를 배우고 목적지 주소로 전달할 포트를 고르는 과정을 설명합니다.

앞선 학습 · IP 주소 / Subnetting까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

스위치는 상대 컴퓨터가 어느 선에 연결됐는지 어떻게 알까요?

30초 핵심 · 스위치는 들어온 데이터의 출발지를 보고 위치를 기억합니다. 보낼 때는 목적지가 연결된 위치를 그 기록에서 찾습니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

MAC 주소
같은 네트워크 구간에서 데이터의 출발지와 목적지를 구분하는 주소입니다. IP 주소와 역할이 다릅니다.
Ethernet 프레임
MAC 주소 등 전달 정보를 붙인 데이터 단위입니다. 출발지 MAC은 Source MAC, 목적지 MAC은 Destination MAC이라고 합니다.
MAC Table
MAC 주소와 포트의 관계를 기억하는 표입니다. FDB라는 이름도 사용합니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 프레임이 들어온 포트를 확인합니다.
  2. 출발지 MAC과 수신 포트를 짝지어 기록하거나 갱신합니다.
  3. 목적지 MAC을 표에서 찾습니다.
  4. 위치를 알면 해당 포트로, 모르면 수신 포트를 제외한 전달 가능한 포트들로 보냅니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
목적지 위치를 앎 · Known Unicast기록된 목적지 포트로 전달합니다.
목적지 위치를 모름 · Unknown Unicast여러 포트로 보내는 Flooding을 합니다. 모두에게 보내는 주소인 Broadcast와는 구분합니다.

05 · 복습

꼭 기억할 세 가지

  • 출발지를 보고 배우고, 목적지를 보고 전달합니다.
  • MAC Table은 MAC과 포트의 관계입니다.
  • 표에 목적지가 없다고 해서 프레임을 항상 버리는 것은 아닙니다.

1단계 · CONCEPT GUIDE

Ethernet / MAC Table

목표는 하나입니다. 스위치가 MAC 주소를 어떻게 배우고, 프레임을 어느 포트로 전달할지 어떻게 결정하는지 설명할 수 있으면 됩니다.

출발지를 보고 배우고, 목적지를 보고 전달합니다.

Source MAC = Learning · Destination MAC = Forwarding

00 · 30초 핵심

딱 두 문장부터 기억하세요.

① 스위치는 들어온 프레임의 Source MAC을 보고 “이 MAC이 어느 포트 쪽에 있는지” 학습합니다.

② Destination MAC을 MAC Table에서 찾아 “어느 포트로 내보낼지” 결정합니다.

01 · FRAME

Ethernet Frame에서 무엇을 볼까요?

처음에는 두 필드만 구분하면 됩니다.

Destination MAC 목적지 MAC MAC Table 조회 → 출력 포트 결정
Source MAC 출발지 MAC 수신 포트와 함께 학습
Payload ARP / IP 등 지금은 세부 내용보다 MAC 두 필드에 집중
02 · SWITCH PROCESS

스위치는 프레임 하나를 이렇게 처리합니다.

1

프레임을 받습니다.

어느 포트로 프레임이 들어왔는지 확인합니다.

2

Source MAC을 학습합니다.

Source MAC → 수신 Port 관계를 MAC Table(FDB)에 기록하거나 갱신합니다.

3

Destination MAC을 찾습니다.

MAC Table 조회 결과에 따라 한 포트로 보내거나 여러 포트로 전달합니다.

가장 중요한 오개념: 스위치는 목적지 MAC을 Flooding해서 배우는 것이 아닙니다. 상대 장비가 보낸 프레임의 Source MAC을 보고 그 장비의 위치를 학습합니다.
03 · KNOWN / UNKNOWN / BROADCAST

세 가지 전달 상황만 구분하세요.

상황Switch가 아는 것동작
Known Unicast목적지 MAC의 포트를 알고 있음그 포트로만 전달
Unknown Unicast목적지 MAC의 포트를 모름수신 포트를 제외한 전달 가능한 포트로 Flooding
Broadcast목적지가 ff:ff:ff:ff:ff:ff같은 Broadcast Domain의 전달 가능한 포트로 전달

Unknown Unicast ≠ Broadcast입니다. 둘 다 여러 포트로 나갈 수 있지만 목적지 MAC 자체가 다릅니다.

04 · FIRST PING

처음 Ping하면 MAC Table은 어떻게 채워질까요?

같은 서브넷의 PC1과 PC2를 가정합니다.

STEP 1

PC1 → ARP Request

SW1은 들어온 프레임의 PC1 Source MAC → PC1 포트를 학습합니다.

STEP 2

PC2 → ARP Reply

이번에는 PC2 Source MAC → PC2 포트를 학습합니다.

STEP 3

PC1 → ICMP Echo

이제 SW1은 PC2의 위치를 알고 있으므로 PC2 포트로만 전달할 수 있습니다.

05 · ARP CACHE vs MAC TABLE

PC가 아는 정보와 Switch가 아는 정보는 다릅니다.

정보주로 누가 보유?기억하는 관계
ARP Cache / ARP TablePC, RouterIP → MAC
MAC Table / FDBSwitch / BridgeMAC → Port
연결해서 생각하기: PC가 목적지 MAC을 알고 있어도, Switch가 그 MAC이 어느 포트에 있는지 모를 수 있습니다. 그 경우 Switch 입장에서는 Unknown Unicast가 될 수 있습니다.
06 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Switch는 Source MAC을 학습합니다.
  • MAC Table은 기본적으로 MAC → Port 관계를 기억합니다.
  • Switch는 Destination MAC으로 출력 포트를 결정합니다.
  • 목적지 위치를 모르면 Unknown Unicast Flooding이 발생할 수 있습니다.
  • ARP Cache와 MAC Table은 서로 다른 정보입니다.
