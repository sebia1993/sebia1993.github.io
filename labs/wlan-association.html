802.11 접속
WPA2 · WPA3

Wi-Fi 이름을 찾은 뒤, 언제 연결하고 언제 암호를 확인할까요?
Authentication·Association·보안 Handshake를 구분하는 것이 오늘의 목표입니다.

1 · 개념서2 · Interactive Lab →
AP 발견 → 인증 → 연결 협상 → Traffic Key 준비 → 보호된 데이터

WPA2와 WPA3는 PMK를 준비하는 방식이 다르고, 이후 4-Way Handshake를 사용합니다.

아래 흐름 그림은 교육 모델입니다. 공개 캡처의 관측 범위는 패킷 근거에서 따로 확인합니다. 우리 AP·태블릿의 직접 패킷 실측은 완료하지 않았습니다.

01 · FOUR QUESTIONS

각 단계가 답하는 질문이 다릅니다.

DISCOVERY

어느 AP가 있지?

Beacon을 수신하거나 Probe Request/Response로 AP 정보를 찾습니다. Probe는 항상 필요한 것은 아닙니다.

AUTHENTICATION

인증 방식은?

WPA2의 기본 접속은 Open System, 새 WPA3-Personal 접속은 SAE를 사용합니다.

ASSOCIATION

이 AP에 연결할까?

기능과 보안 조건을 협상합니다. 성공 응답과 보안 Handshake 완료는 다른 상태입니다.

4-WAY HANDSHAKE

키를 준비했나?

PMK를 바탕으로 Traffic Key를 도출·설치하고, 보호된 데이터 통신으로 진행합니다.

02 · WPA2 vs WPA3 PERSONAL

SAE는 Association 전에, 4-Way는 그 뒤에.

WPA2-PERSONAL · 기본 최초 접속

Open System → Association → 4-Way

  1. Open System Authentication요청·성공 응답. 여기서는 Wi-Fi 암호를 검증하지 않습니다.
  2. Association요청·성공 응답으로 연결 조건을 정합니다.
  3. EAPOL-Key M1 → M2 → M3 → M4PSK 기반 PMK에서 각 측이 키를 도출하고, 공유한 키 자료를 확인합니다.
  4. Protected Data암호화 프레임과 실제 통신 성공을 함께 확인합니다.
Open Authentication 성공 ≠ 올바른 암호.
Association 성공도 4-Way 완료를 뜻하지 않습니다.
WPA3-PERSONAL · 새 SAE 접속

SAE → Association → 4-Way

  1. SAE Commit / Confirm802.11 Authentication 단계에서 양측이 교환하여 PMK를 도출합니다.
  2. AssociationSAE 성공 뒤 연결 조건을 협상합니다.
  3. EAPOL-Key M1 → M2 → M3 → M4SAE로 준비한 PMK를 바탕으로 Traffic Key를 도출·설치합니다.
  4. Protected Data데이터 통신 성공은 별도 확인이 필요합니다.
새 접속과 캐시 재접속을 구분하세요.
PMKID 캐시를 사용하면 SAE 교환이 생략될 수 있습니다. SAE가 안 보인다는 이유만으로 WPA2라고 단정하지 않습니다.
03 · MESSAGE SEQUENCE

4-Way의 방향과 역할을 읽어 보세요.

STA-A · 태블릿Supplicant
AP-AAuthenticator
  1. M1 · AP → STAANonce 전달
  2. M2 · STA → APSNonce + MIC
  3. M3 · AP → STA키 설치에 필요한 정보 · 보호된 GTK
  4. M4 · STA → AP확인 응답

교육 모델 · 화살표는 메시지 방향입니다. 실제 캡처의 프레임 번호·시간을 표시한 그림이 아닙니다.

PMK는 M1에 실려 오지 않습니다.

PMK는 양측이 이미 준비한 키 자료입니다. M1의 ANonce와 M2의 SNonce는 키 도출에 쓰이는 값이며 PMK 자체가 아닙니다.

  • MIC: 메시지 무결성과 키 보유 확인에 쓰입니다.
  • PTK / GTK: 각각 개별 단말 통신과 그룹 통신에 사용하는 키입니다.
  • 재전송: 패킷이 네 개보다 많아도 4-Way일 수 있습니다.
  • 판독: 같은 STA/AP, Pairwise Key Type, 방향, replay counter를 함께 봅니다. Group Key 교환과 섞지 않습니다.
캡처에 M3가 없다는 사실만으로 암호 오류를 확정하지 않습니다. 캡처 누락 가능성과 AP/STA 상태도 확인해야 합니다.
04 · WHERE DID IT STOP?

실패한 단계를 먼저 찾습니다.

Association 실패

Association 응답이 실패 상태라면 연결 조건 협상에서 멈춘 것입니다. 그 뒤 4-Way가 완료됐다고 설명할 수 없습니다.

보안 Handshake 실패

틀린 WPA2 암호에서도 Auth/Assoc는 성공할 수 있습니다. 성공한 연결 협상 뒤 키 교환이 멈췄는지, AP/STA 로그와 통신 결과로 확인합니다. Auth/Assoc가 항상 성공한다는 뜻은 아닙니다.

복구까지 확인: 올바른 lab 설정으로 되돌린 뒤 새 연결의 4-Way 완료와 보호된 데이터 통신 성공을 확인합니다.
05 · SAE / PMF / DATA

인증과 관리 프레임 보호는 별개입니다.

SAE 선택과 PMF 협상 확인

AP의 “WPA3 지원” 표시는 가능한 방식의 광고입니다. 실제 접속이 SAE를 선택했는지 Association의 RSN AKM과 PMF capability/requirement를 함께 확인합니다.

MFPC는 보호 기능 지원(Capable), MFPR은 사용 요구(Required)입니다. AP 광고에서 MFPC/MFPR 순서로 1/1은 필수, 1/0은 선택, 0/0은 미지원 광고를 뜻합니다. 양측이 모두 MFPR=1이어야 한다는 뜻은 아닙니다.

WPA2/WPA3 혼합 모드 접속을 pure-mode 증거로 보지 않습니다. 공개 SAE 표본의 0/0과 별도 WPA2 MFP 표본의 1/1 비교도 각 표본의 관측입니다.

SAE 관측 ≠ WPA3 요구사항 전체 확인.
다른 WPA2 표본의 PMF를 합쳐 WPA3의 PMF 관측으로 만들지 않습니다.

PMF ≠ 모든 프레임의 암호화

PMF는 연결 후 Deauthentication, Disassociation, 일부 Action 같은 robust management frame을 보호합니다. 데이터 암호화와 역할이 다르며 Beacon·초기 Auth/Assoc까지 모두 암호화한다는 뜻은 아닙니다.

WPA3 암호와 4-Way만 알아도 데이터를 복호화할 수 있는 것은 아닙니다. Wireshark에는 해당 연결의 PMK가 필요합니다.
