Leaf–Spine / VXLAN / EVPN

Server A에서 Server B로 가는 길을 따라가며, 실제 운반망과 그 위의 논리 네트워크가 각각 무엇을 맡는지 설명합니다.

앞선 학습 · VLAN, 라우팅, BGP를 연결합니다. 로드맵의 직전 주제는 Network Automation입니다.

읽는 시간 약 7~8분장비 4대 · 서버 2대의 같은 예시

01 · 질문과 그림으로 시작

서로 다른 스위치에 연결된 서버를 같은 네트워크로 묶으려면?

데이터센터에는 서비스를 실행하고 데이터를 저장하는 서버가 모여 있습니다. 사용자와 서버 사이뿐 아니라, 서버끼리도 데이터를 주고받습니다. 서버가 늘어날 때 연결을 확장하면서도, 서비스별 네트워크는 나누어 유지해야 합니다.

30초 핵심 · 먼저 서버 사이를 오갈 수 있는 IP 운반망을 만듭니다. 그 위에서 원래 프레임에 운반용 정보를 덧붙여 보내면, 떨어진 서버도 같은 논리 네트워크로 묶을 수 있습니다.

Leaf / Spine
Leaf는 서버를 연결하고, Spine은 Leaf 사이를 잇습니다. 이 예시의 Leaf는 단순 L2 스위치가 아니라 L3 전달 기능도 사용하는 장비입니다.
Fabric
여러 스위치가 함께 만드는 연결망입니다. 여기서는 각 Leaf를 모든 Spine에 연결하여 구성합니다.

길이 두 개면 데이터를 두 번 보낼까요? 비용이 같은 여러 경로를 이용하는 ECMP를 구성할 수 있습니다. 일반적으로 흐름별로 길을 골라 분산하며, 같은 패킷을 두 길로 복제하는 뜻은 아닙니다. 이 예시에서는 Switch C 경로 하나를 따라갑니다.

02 · 같은 연결을 두 가지 관점으로 보기

운반하는 길과, 그 길 위에 만든 네트워크

기존 VLAN 학습과 연결하면 · VLAN은 연결된 L2 구간을 나누는 방식이었습니다. 여기서는 그 L2 연결을 IP 운반망 너머로 이어 줍니다. 이때 원래 Ethernet 프레임을 IP 패킷 안에 넣는 방식이 VXLAN입니다.

03 · 원래 프레임에 운반용 정보를 덧붙이기

서버의 목적지와 운반망의 목적지는 다릅니다.

이 예시에서 Switch A는 Server A의 프레임을 감싸고, Switch B는 감싼 정보를 벗겨 Server B로 전달합니다. VXLAN의 이런 입구·출구 역할을 VTEP(터널 끝점)이라고 부릅니다.

VNI
VXLAN의 24비트 네트워크 식별자입니다. 이 예시에서 10100은 두 서버가 속할 논리 L2 네트워크를 뜻합니다. 로컬 VLAN을 이 VNI에 연결하며, VLAN 번호와 VNI 숫자가 같을 필요는 없습니다.

이번 범위 · Server A/B는 같은 서브넷·같은 L2 VNI에 있습니다. 서로 다른 VNI 사이의 라우팅은 다루지 않습니다. VXLAN으로 감싸는 것 자체가 데이터 암호화를 뜻하지는 않습니다.

04 · 목적지 위치를 알고 있을 때의 전달 순서

그런데 Switch A는 “Server B가 Switch B 뒤에 있다”는 것을 어떻게 알까요?

EVPN은 BGP로 끝점의 도달 정보를 주고받는 제어 기능입니다. 이 예시에서는 Server B의 MAC 주소와 도달할 VTEP 정보를 배워 둡니다. EVPN은 위치를 알리고, VXLAN은 실제 프레임을 운반합니다.

시작 조건 · Underlay 경로, VNI 연결, EVPN 경로와 원격 MAC 전달 정보가 준비되어 있고, Server A도 ARP로 Server B의 MAC 주소를 알고 있습니다. 따라서 이미 아는 한 목적지로 보내는 Known Unicast만 살펴봅니다.

  1. Server A → Switch A
    Server B가 같은 서브넷이므로 Server B의 MAC 주소를 목적지로 한 프레임을 보냅니다.
  2. Switch A가 감쌉니다.
    Server B의 MAC에 대응하는 원격 VTEP가 Switch B임을 확인합니다. VNI 10100과 바깥쪽 목적 IP 192.0.2.12를 붙입니다.
  3. Switch C가 중계합니다.
    선택된 Underlay 경로를 따라 Switch B로 IP 패킷을 전달합니다. 원래 서버 프레임의 목적지를 다시 결정하는 단계가 아닙니다.
  4. Switch B → Server B
    VNI 10100에 대응하는 로컬 L2 네트워크를 확인하고 VXLAN 포장을 벗깁니다. 해당 네트워크에서 Server B의 포트로 원래 프레임을 전달합니다.

두 가지 “라우팅”을 구분하세요. 운반망에서는 바깥쪽 IP 패킷을 라우팅합니다. 하지만 여기서 두 서버는 같은 L2 네트워크에 있으므로, Server A의 원래 패킷을 다른 서브넷으로 라우팅하는 예시는 아닙니다.

Leaf–Spine이라고 반드시 VXLAN을 쓰는 것은 아닙니다. 또 VXLAN 자체가 EVPN을 필수로 요구하는 것은 아닙니다. 여기서는 함께 사용하는 한 가지 구성을 배우고 있습니다.

06 · 복습

꼭 기억할 네 가지

  • Leaf는 서버를 연결하고 Spine은 Leaf 사이를 잇습니다.
  • Underlay는 IP 운반망, Overlay는 그 위의 논리 네트워크입니다.
  • VTEP가 VXLAN 포장을 붙이고 벗기며, VNI로 네트워크를 구분합니다.
  • EVPN은 도달 정보를 알리고 VXLAN은 실제 데이터를 운반합니다.

내 말로 설명하기

Server B의 IP는 10.10.10.12인데, 중간의 Switch C가 192.0.2.12를 목적지로 보는 이유는 무엇일까요?

설명 방향 확인하기

10.10.10.12는 원래 프레임 안의 서버 목적지입니다. Switch A가 그 프레임을 Switch B까지 운반하려고 바깥쪽 IP 정보를 붙였기 때문에, Switch C는 목적 VTEP 주소인 192.0.2.12를 보고 전달합니다.

  • RFC 8365 · EVPN을 사용하는 네트워크 가상화 Overlay§4, §5.1 · EVPN 제어 기능과 VXLAN 데이터 전달의 결합. Standards Track 문서입니다.

이 그림에서는 Leaf가 VTEP를 겸하고 Spine은 L3 중계만 맡습니다. 실제 설계에서는 역할이 달라질 수 있습니다. EVPN의 모든 경로 유형이나 BGP 세션 배치를 그린 것은 아닙니다.
