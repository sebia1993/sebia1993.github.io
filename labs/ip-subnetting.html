IP 주소 / Subnetting

목표는 하나입니다. 내 IP와 Prefix/Mask를 이용해 목적지가 같은 Subnet인지 판단하는 원리를 설명할 수 있으면 됩니다.

이 페이지에서는 판단 원리만 이해합니다.CLI, PCAP, 장비 설정은 숨겨두고 검증된 핵심 Mental Model만 학습합니다.
1 · 개념서2 · Interactive Lab
Mask를 적용한 Network Prefix가 같으면 on-link, 다르면 gateway 경유입니다.

IP + Prefix/Mask → Network Prefix 계산 → 비교 → 전달 방식 결정

00 · 30초 핵심

딱 세 문장만 먼저 기억하세요.

① /25는 IPv4 32비트 중 앞 25비트가 Network Prefix라는 뜻입니다.

② 송신자는 자신의 Mask를 내 IP와 목적지 IP에 적용해 Network Prefix를 비교합니다.

③ 같으면 목적지를 직접 전달 대상으로 보고, 다르면 Routing 결과의 gateway/next-hop을 사용합니다.

01 · PREFIX / MASK

/25는 주소 공간을 어디서 나눌까요?

/25 = 255.255.255.128

10.77.10.0/25주소 범위 .0 ~ .127일반 Host 예: .10, .20
10.77.10.128/25주소 범위 .128 ~ .255일반 Host 예: .140
검증된 예: 10.77.10.10/25의 Network는 10.77.10.0/25, 10.77.10.140/25의 Network는 10.77.10.128/25였습니다.
02 · 판단 순서

보내기 전에 먼저 “같은 Network인가?”를 판단합니다.

1

내 Network 계산

내 IPv4 주소에 내 인터페이스의 Mask를 적용합니다.

2

목적지 Network 계산

목적지 IPv4에도 같은 Mask를 적용합니다.

3

두 결과 비교

같으면 on-link, 다르면 gateway/next-hop 경유로 판단합니다.

순서가 중요합니다. ARP가 먼저 목적지를 정하는 것이 아닙니다. 먼저 IP/Mask와 Routing으로 전달 대상을 판단한 뒤 필요한 이웃 MAC을 확인합니다.
03 · 두 가지 예시

같은 /25에서도 목적지에 따라 판단이 달라집니다.

ON-LINK

PC1 .10/25 → PC3 .20/25

둘 다 10.77.10.0/25에 속합니다.

실제 검증에서도 PC1은 .20을 직접 ARP했고 ping 3/3이 성공했습니다.

결론 · 목적지를 직접 전달 대상으로 판단
VIA GATEWAY

PC1 .10/25 → PC2 .140/25

PC1은 10.77.10.0/25, PC2는 10.77.10.128/25입니다.

실제 검증에서는 PC1이 gateway .1을 ARP했고 IPv4 Destination은 계속 .140을 유지했습니다.

결론 · gateway/next-hop을 통해 전달
04 · 대표 오설정

Mask를 너무 넓게 잡으면 판단 자체가 바뀝니다.

NORMAL · /25

.10과 .140은 다른 Subnet

PC1은 .140을 off-link로 판단하고 gateway .1을 next-hop으로 사용합니다.

10.77.10.0/25 ≠ 10.77.10.128/25
WRONG MASK · /24

.140을 같은 Subnet으로 오판

PC1만 /24로 바꾸면 .10과 .140이 모두 10.77.10.0/24로 계산됩니다.

검증 Lab에서는 Proxy ARP를 끈 상태에서 PC1이 .140에 직접 ARP했고 Reply가 없어 원격 ICMP를 보내기 전에 실패했습니다.

잘못된 Mask → 잘못된 on-link 판단
✓

실제 검증 완료: Cisco 3725 IOS 12.4(15)T14 + VPCS/PNETLab에서 /25 → /24 → /25 변화와 ARP/ICMP 흐름을 CLI와 PCAP으로 교차 확인했습니다. 이 구현 환경에서 확인한 장애 현상을 모든 OS의 세부 동작으로 일반화하지 않습니다.

06 · REVIEW

여기까지 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • IPv4 Prefix는 0~32비트 길이로 Network Prefix를 표현합니다.
  • 같은 Subnet 판단은 송신자의 Mask 기준입니다.
  • Network Prefix가 같으면 on-link, 다르면 gateway/next-hop 경유입니다.
  • off-link여도 IPv4 Destination이 gateway IP로 바뀌는 것은 아닙니다.
  • 잘못된 Mask는 ARP 이전의 전달 판단 자체를 틀리게 만들 수 있습니다.
