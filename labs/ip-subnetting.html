IP 주소 / Subnetting

목표는 하나입니다. 내 IP와 네트워크 범위 기준(Prefix/Mask)을 이용해 목적지가 같은 네트워크(Subnet)인지 판단하는 원리를 설명할 수 있으면 됩니다.

이 페이지에서는 판단 원리만 이해합니다.CLI, PCAP, 장비 설정은 숨겨두고 검증된 핵심 판단 원리만 학습합니다.
1 · 개념서2 · Interactive Lab
내 IP와 목적지 IP가 같은 네트워크 범위인지 먼저 판단합니다.

같은 범위면 같은 Subnet(on-link), 다른 범위면 Gateway를 통해 다음 경로로 보냅니다.

00 · 30초 핵심

딱 세 문장만 먼저 기억하세요.

① IP 주소는 네트워크에서 장치를 구분하는 주소입니다.

② Subnet Mask는 내 IP와 목적지 IP가 같은 네트워크 범위인지 계산할 때 쓰는 기준입니다.

③ 같은 범위면 목적지 쪽으로 직접 전달하고, 다른 범위면 Gateway를 다음 전달 대상으로 사용합니다.

01 · 먼저 알아둘 말

처음 보는 용어는 이 정도 뜻으로 시작하면 됩니다.

정확한 세부 규칙보다 먼저, 문장에서 이 말이 무엇을 가리키는지만 익힙니다.

IP 주소

네트워크에서 장치를 구분하기 위한 주소입니다. 이 페이지에서는 10.77.10.10처럼 IPv4 주소를 사용합니다.

Subnet

하나의 네트워크를 일정한 범위로 나눈 단위입니다. 쉽게 말해 “같은 네트워크 동네”라고 생각하면 됩니다.

Prefix · /25

IPv4 주소는 32개의 비트로 표현합니다. 비트는 0 또는 1로 표현하는 한 자리입니다. /25라면 앞 25비트를 네트워크 구분에 사용한다는 뜻입니다.

Subnet Mask

Prefix가 정한 네트워크 경계를 숫자 4묶음으로 표시한 값입니다. 예를 들어 /25는 255.255.255.128로도 표시할 수 있습니다.

Default Gateway

내 네트워크 밖으로 데이터를 보내주는 장치인 라우터의 주소입니다. 다른 Subnet으로 갈 때 먼저 이 장치에 전달합니다.

ARP

같은 네트워크 안에서 실제로 데이터를 보낼 상대의 MAC 주소를 확인하는 절차입니다. 이 페이지에서는 “누구의 MAC을 찾는가”만 보면 됩니다.

용어 읽는 법: 같은 Subnet을 on-link, 다른 Subnet을 off-link라고 부릅니다. next-hop은 목적지로 가기 위해 “다음에 넘길 장치”라는 뜻이며, 이 페이지의 off-link 예시에서는 Gateway가 next-hop입니다.
02 · PREFIX / MASK

/25는 왜 .127과 .128 사이에서 나뉠까요?

/25 = 255.255.255.128

검증된 예: 10.77.10.10/25의 Network는 10.77.10.0/25, 10.77.10.140/25의 Network는 10.77.10.128/25였습니다.
03 · 판단 순서

보내기 전에 먼저 “같은 Subnet인가?”를 판단합니다.

순서가 중요합니다. ARP가 “어디로 보낼지”를 결정하는 것이 아닙니다. 먼저 IP와 Subnet Mask로 같은 Subnet인지 판단하고, 다른 Subnet이면 Routing 결과에서 Gateway/next-hop을 고른 뒤 ARP로 그 이웃의 MAC 주소를 확인합니다.
04 · 두 가지 예시

같은 /25에서도 목적지에 따라 판단이 달라집니다.

05 · 대표 오설정

Mask를 너무 넓게 잡으면 판단 자체가 바뀝니다.

07 · REVIEW

여기까지 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • IPv4 Prefix는 0~32비트 길이로 Network Prefix를 표현합니다.
  • 같은 Subnet 판단은 송신자의 Mask 기준입니다.
  • Network Prefix가 같으면 on-link, 다르면 gateway/next-hop 경유입니다.
  • off-link여도 IPv4 Destination이 gateway IP로 바뀌는 것은 아닙니다.
  • 잘못된 Mask는 ARP 이전의 전달 판단 자체를 틀리게 만들 수 있습니다.
내 말로 설명하기

/25가 만드는 Network Prefix를 두 주소에서 각각 계산해 설명해 보세요.
