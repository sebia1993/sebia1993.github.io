02 · 선행 개념

지금 필요한 용어는 세 가지

IP는 통신 상대를 식별하는 주소, Mask는 Network 부분을 나누는 기준, Gateway는 다른 망으로 가는 다음 전달 대상입니다.

03 · 핵심 개념

Prefix는 Network 부분의 길이

/25는 32비트 중 앞 25비트가 Network라는 뜻이며 Mask는 255.255.255.128입니다.

192.0.2.0/25의 일반 Host 범위는 .1 ~ .126, Broadcast는 .127입니다. .140은 다음 망인 192.0.2.128/25에 속합니다.

출발지와 목적지에 송신자의 Mask를 각각 적용한 Network 값이 같으면 같은 Subnet으로 판단합니다.

다르다 · OFF-LINK

목적지를 직접 이웃으로 보지 않습니다. Routing Table을 보고 이 과정의 기본 모델에서는 Default Gateway를 다음 홉으로 사용합니다.

13 · Packet 자세히 보기: IP와 Ethernet은 역할이 다릅니다

시뮬레이터의 Packet 상세는 합성 필드입니다. 예를 들어 PC1→PC2 첫 ICMP 요청은 Source IP .10, Destination IP .140, Ethernet Destination MAC은 R1 왼쪽입니다. R1은 오른쪽 링크에서 Source/Destination MAC을 새로 만들고 TTL을 줄입니다. NAT는 없습니다.

ARP는 IPv4 패킷이 아니므로 ARP의 “찾는 IP”와 IPv4 Header의 “Destination IP”를 같은 필드로 읽으면 안 됩니다. 실제 캡처는 arp || icmp로 구간을 좁히고 목적지·ICMP 식별자·순번을 함께 비교합니다.

그림과 MAC은 합성 예시이고 실제 GNS3 결과가 아닙니다. 기존 ARP 과정의 실제 관측은 별도 실험임을 확인하고 비교하세요.

14 · 심화: /31, /32, Proxy ARP와 조건의 한계

/31은 RFC 3021의 Point-to-Point 링크 문맥에서 두 주소를 쓰는 특례입니다. 일반 LAN Network/Broadcast 공식을 그대로 적용하지 않습니다. /32는 단일 Host Route를 나타냅니다. /0 계산에는 예약·특수 IPv4 범위도 들어 있으므로 계산된 주소 수 전체를 실제 Host에 할당할 수 있다는 뜻은 아닙니다.

이 파일럿은 추가 Host/Static Route 없음, Proxy ARP 꺼짐, NAT 없음, 정상 링크를 가정합니다. Proxy ARP가 켜져 있거나 더 구체적인 경로가 있으면 잘못된 Mask에서도 관측이 달라질 수 있습니다. 서로 다른 Mask 설정과 반환 경로도 따로 확인해야 합니다.

CLI·주소 대응·캡처 위치는 IP/Subnetting Lab Plan에 있습니다. 문서 주소는 TEST-NET, 실제 계획은 격리된 사설 주소이며 두 집합을 같은 캡처로 취급하지 않습니다.

EXPLAIN IN MY OWN WORDS · 마지막 점검

정답을 외우지 말고 자신의 말로 설명해 보세요.

1. /25에서 192.0.2.10과 192.0.2.140이 왜 다른 Subnet인가?

/25는 마지막 Octet을 0~127과 128~255로 나눕니다. .10의 Network는 192.0.2.0/25, .140의 Network는 192.0.2.128/25이므로 서로 다릅니다.

2. 다른 Subnet으로 보낼 때 왜 IP 목적지는 Gateway IP로 바뀌지 않는가?

IP 목적지는 최종 도착지입니다. Gateway는 현재 링크에서 사용할 다음 홉이므로 첫 Ethernet 프레임의 목적지 MAC이 Gateway MAC이 됩니다. NAT 같은 별도 기능이 없다면 목적지 IP는 최종 Host를 유지합니다.

3. Mask가 너무 넓으면 왜 원격 Host에게 직접 ARP할 수 있는가?

송신자가 잘못된 Mask로 원격 주소를 같은 Network라고 계산하기 때문입니다. Host의 on-link 판단이 잘못되면 Routing Table의 Gateway보다 목적지 직접 ARP를 선택할 수 있습니다.

4. ARP 실패만 보고 상대 PC Down이라고 단정하면 안 되는 이유는?

ARP 대상 자체가 잘못됐을 수 있습니다. 잘못된 Mask라면 원격 목적지를 직접 ARP하고, 잘못된 Gateway라면 존재하지 않는 다음 홉을 ARP할 수 있으므로 먼저 IP/Mask/Route/Next-hop을 확인해야 합니다.
