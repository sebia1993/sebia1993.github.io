09 · 1단계 CONCEPT GUIDE

LACP / Link Aggregation

여러 물리 링크의 묶음과 개별 통신에 선택되는 링크를 구분합니다.

앞선 학습 · STP / RSTP까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

케이블 두 개를 하나처럼 쓰면 한 통신도 무조건 두 배 빨라질까요?

30초 핵심 · 여러 케이블을 하나의 논리 링크로 묶을 수 있습니다. 하지만 한 통신 흐름은 선택 기준에 따라 그중 한 링크를 사용할 수 있어, 케이블 수가 곧 한 통신의 배속은 아닙니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

LAG / Member
여러 물리 링크의 논리 묶음이 LAG이고, 그 묶음의 개별 링크가 Member입니다. Cisco에서는 Port-Channel이라고도 합니다.
LACP
양쪽 장비가 묶음에 사용할 링크 정보를 주고받는 절차입니다.
Flow / Hash
Flow는 같은 통신으로 묶어 보는 흐름입니다. Hash는 주소 등의 입력으로 사용할 멤버를 고르는 방식입니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 양쪽 장비가 LACP 정보를 교환합니다.
  2. 조건이 맞는 링크들을 하나의 LAG로 묶습니다.
  3. 각 통신 흐름에 사용할 멤버를 선택합니다.
  4. 멤버 상태와 묶음 상태를 나눠 확인합니다. 남은 멤버가 있으면 묶음이 유지될 수 있습니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
멤버 하나 사용 불가남은 멤버로 묶음을 유지할 수 있습니다. 무손실을 보장하는 말은 아닙니다.
모든 멤버 사용 불가이 예제에서는 묶음도 내려가고 반대편 통신이 끊깁니다.

05 · 복습

꼭 기억할 세 가지

  • LAG 하나와 물리 링크 하나는 다릅니다.
  • 한 Flow가 모든 링크를 번갈아 쓰는 것은 아닙니다.
  • 묶음과 각 멤버의 상태를 함께 봅니다.

1단계 · CONCEPT GUIDE

LACP / Link Aggregation

목표는 하나입니다. 여러 Physical Member가 하나의 Logical LAG을 만들고, Flow별 Member 선택과 Member 장애가 어떻게 다르게 나타나는지 설명할 수 있으면 됩니다.

“Cable 두 개 = 모든 Packet이 절반씩”이라고 생각하지 않습니다.협상, Logical Bundle, Flow Hash, Member Failure를 순서대로 연결합니다.
1 · 개념서2 · Interactive Lab
표준 기준: IEEE 802.1AX의 핵심 단위는 Link Aggregation Group (LAG)입니다. Port-Channel, EtherChannel, Po1은 이번 Cisco 구현에서 보이는 용어·표시입니다.
LACP는 Member를 묶고, Hash는 Flow마다 Member 하나를 고릅니다.

Negotiation → LAG → Flow Hash → Member Failure → Bundle State

00 · 30초 핵심

Physical Member와 Logical LAG을 따로 봅니다.

① 협상: active는 LACP 협상을 시작하고 passive는 수신 LACP에 응답합니다.

② Bundle: 호환되는 M1/M2가 묶이면 상위 기능에는 하나의 Logical LAG로 보이며, 이번 Cisco 구현에서는 Po1으로 표시됩니다.

③ Hash: 한 Flow는 Hash 결과에 따라 한 Member에 일관되게 매핑될 수 있고, 다른 Flow는 다른 Member를 사용할 수 있습니다.

④ 장애: Member 하나가 unavailable이어도 남은 Member가 있으면 Po1은 유지될 수 있지만, 모든 Member가 사라지면 Po1도 Down됩니다.

01 · LACP BUNDLE

두 Physical Link가 하나의 Logical Link가 됩니다.

SW1

active

LACPDU를 먼저 보내 협상을 시작합니다. 이번 Baseline에서 M1/M2 두 Member가 모두 Bundled됐습니다.

SW2

passive

active 쪽의 LACPDU에 응답했고 Actor/Partner 정보가 양쪽에서 일치했습니다.

UPPER LAYER

Port-channel1

STP에서는 Physical M1/M2 두 개가 아니라 Po1 하나의 Forwarding Port로 확인됐습니다.

반대로 passive/passive는? Clean 상태에서 양쪽 모두 passive로 구성하자 정상 Bundle이 형성되지 않았습니다. SW1만 active로 바꾸자 다시 두 Member가 Bundled되고 Po1이 정상화됐습니다.
02 · FLOW HASH

한 Flow를 Packet마다 번갈아 보내는 방식으로 이해하지 않습니다.

PC1A → PC2ASource MAC 00:50:79:66:68:41 · 5/5 Request
PC1B → PC2ASource MAC 00:50:79:66:68:42 · 5/5 Request
M2
M1
src-mac MethodPC1A Flow는 M2에서만 관찰
src-mac MethodPC1B Flow는 M1에서만 관찰
중요: 원래 src-dst-ip 검증에서는 8개 Flow가 모두 M1을 사용해 분산을 입증하지 못했습니다. 이를 숨기지 않고, 재검증에서 src-mac을 사용해 두 Flow가 M2/M1으로 실제 분리되는 것을 확인했습니다. 50:50·단일 Flow 2배 처리량·내부 Hash 공식은 검증하지 않았습니다.
03 · MEMBER FAILURE

한 Member 장애와 Bundle 전체 장애는 다릅니다.

ONE MEMBER UNAVAILABLE

M1 양단 unavailable · M2는 Bundled

재검증에서 양쪽 M1을 하나의 장애 사건으로 Down시켰을 때 Po1은 Up을 유지했고, Core Flow는 M2로 이동해 100 Request / 100 Reply를 유지했습니다.

M1 ✕ · M2 ✓ · Po1 UP · End-to-End ✓
ALL MEMBERS UNAVAILABLE

M1 + M2 모두 Down

원래 검증에서 두 Member를 모두 Down시키자 Po1도 Down됐고 Remote 통신은 실패했습니다. 두 Member를 복구하자 Po1과 통신이 모두 정상화됐습니다.

M1 ✕ · M2 ✕ · Po1 DOWN · End-to-End ✕
원래 LACP-05 FAIL도 보존합니다. SW1 한쪽 M1만 administratively shutdown한 첫 Run에서는 Forward는 M2로 이동했지만 Return Path가 정상 전환되지 않아 자동 복구에 실패했습니다. 재검증은 “Member 전체가 양단에서 unavailable”한 조건으로 바꿔 PASS했으며, 이를 실제 Cable Carrier 동작까지 완전히 규명했다고 확대 해석하지 않습니다.
04 · NORMAL FLOW

Bundle을 볼 때는 네 단계를 순서대로 확인합니다.

1

LACP 협상

Actor/Partner와 Key가 호환되는 Member인지 확인합니다.

2

Member Bundled

M1/M2가 Po1의 In-use Member로 들어옵니다.

3

Logical Link

STP 등 상위 기능은 Po1 하나의 Link로 봅니다.

4

Flow Hash

각 Flow의 Hash 결과가 실제 Member를 선택합니다.

5

Failure Check

Po1과 각 Member 상태를 함께 봐야 장애 범위를 구분할 수 있습니다.

05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • active/passive는 LACP Bundle을 형성할 수 있지만 passive/passive는 협상을 시작하지 않습니다.
  • M1/M2가 묶이면 상위 Layer에는 Po1 하나로 보입니다.
  • Hash는 Flow별 Member 선택이며 Packet-by-Packet Striping으로 일반화하지 않습니다.
  • Member 하나 Down과 Po1 전체 Down은 다른 장애입니다.
  • Po1이 Up이어도 각 Member State를 별도로 확인해야 합니다.
내 말로 설명하기

“M1이 죽었는데 Po1은 왜 아직 Up일 수 있을까?”

Bundle, Member, Hash, Remaining Member라는 네 단어를 사용해 설명할 수 있다면 충분합니다.
