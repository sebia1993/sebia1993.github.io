1단계 · CONCEPT GUIDE

VLAN / Access / Trunk

목표는 하나입니다. Host의 Untagged Frame이 Access VLAN에 들어가고, Switch 사이 Trunk에서는 VLAN 정보가 어떻게 유지되는지 설명할 수 있으면 됩니다.

이 페이지에서는 원리만 이해합니다.CLI나 PCAP 원문을 외우지 않습니다. Access / Trunk / Tag / Native / Allowed의 관계만 잡고 2단계에서 직접 확인합니다.
1 · 개념서2 · Interactive Lab
Access에서는 VLAN을 정하고, Trunk에서는 VLAN 정보를 들고 이동합니다.

Access VLAN → 802.1Q VLAN ID → 같은 VLAN의 Access Port

Vendor-Neutral Core: 학습 기준은 VLAN 분리와 IEEE 802.1Q의 Tagged/Untagged 전달입니다. Access / Trunk / Native / Allowed는 이번 Cisco IOL 검증에서 사용한 구성·운영 용어로 보고, 표준 개념과 구분합니다.
00 · 30초 핵심

Tagged인지보다 먼저 “어느 VLAN 소속인가”를 봅니다.

① Access Port: End Host의 일반 Ethernet Frame은 Untagged로 들어오고, Switch는 Port 설정으로 VLAN을 정합니다.

② Trunk: 여러 VLAN을 한 Link로 보내므로 Non-native VLAN은 802.1Q VLAN ID를 붙여 구분합니다.

③ Native VLAN: 기본 Cisco 802.1Q 동작에서는 Native VLAN의 Trunk Frame이 Untagged일 수 있습니다.

④ 장애: Link가 Up이어도 Allowed VLAN 누락이나 Access VLAN mismatch로 특정 VLAN만 끊길 수 있습니다.

01 · ACCESS → TRUNK → ACCESS

같은 VLAN Frame도 링크에 따라 모양이 달라집니다.

검증한 VLAN 20 경로를 그대로 단순화했습니다.

PC20AUntagged
→ SW1Access VLAN 20
SW1 ↔ SW2802.1Q · VLAN 20
→ SW2VLAN 20 유지
PC20BUntagged
핵심: Host가 VLAN Tag를 붙이는 것이 아니라, 일반 Access 환경에서는 Switch가 Access Port 설정으로 VLAN을 분류합니다. Trunk 구간에서만 VLAN 20이라는 정보가 802.1Q Tag로 Wire에 나타납니다.
02 · 802.1Q

Trunk 하나에서 VLAN이 섞이지 않는 이유

1

Host Frame 유입

PC20A는 Untagged Frame을 Access Port로 보냅니다.

2

VLAN 20 분류

SW1은 Port 설정으로 이 Frame을 VLAN 20에 넣습니다.

3

Trunk Tag

VLAN 20은 Native가 아니므로 802.1Q VLAN ID 20을 붙여 보냅니다.

4

SW2 분리 유지

SW2는 VLAN ID 20을 기준으로 VLAN 20 안에서만 전달합니다.

5

Access Egress

PC20B 쪽 Access Link에서는 다시 Untagged Frame으로 나갑니다.

Broadcast도 동일합니다. VLAN 20 ARP Broadcast는 Trunk에서 VLAN 20으로 표시되고 VLAN 20 Access Port로는 가지만, VLAN 10 Access Port에는 전달되지 않았습니다.
03 · NATIVE / ALLOWED

Trunk에는 두 가지 설정을 더 구분해야 합니다.

Non-native · VLAN 10 / 20

Tagged

검증 Trunk에서 VLAN 10과 20 Data Traffic은 802.1Q Tag를 가진 Frame으로 관찰됐습니다.

Native · VLAN 99

기본 Cisco 동작은 Untagged

양쪽 Native VLAN을 99로 맞춘 상태에서 VLAN 99 Traffic은 같은 Trunk에서 Untagged로 관찰됐습니다.

Allowed · 10,20,99

통과 가능한 VLAN 목록

Allowed 목록에서 VLAN 20을 제거하자 Trunk Port는 Up이었지만 VLAN 20 Data Traffic은 더 이상 건너지 못했습니다.

주의: Native VLAN Tagging 기능을 별도로 활성화하면 실제 Wire 형식은 달라질 수 있습니다. 이번 검증은 global native tagging이 비활성인 Cisco IOL L2 환경입니다.
04 · 두 가지 대표 장애

“Link Up”과 “그 VLAN이 통신 가능”은 같은 말이 아닙니다.

ALLOWED VLAN 누락

SW1 Trunk에서 VLAN 20 제거

PC20A의 ARP는 SW1 Access Link까지 왔지만 Trunk에는 나오지 않았습니다. VLAN 10과 99는 계속 통신했습니다.

PC20A → SW1 ✓ → Trunk VLAN20 ✕ → SW2 / PC20B
ACCESS VLAN MISMATCH

PC20B Port만 VLAN 20 → 10

VLAN 20 ARP는 Trunk를 정상 통과했지만 SW2의 PC20B Access Link로는 나오지 않았습니다. 물리 Port와 Trunk는 계속 Up이었습니다.

PC20A → SW1 → Trunk VLAN20 ✓ → SW2 → PC20B Port(VLAN10) ✕
복구도 확인했습니다. Allowed VLAN 20과 Access VLAN 20을 각각 원복한 뒤 통신이 정상화됐습니다. Allowed VLAN 복구 직후에는 이번 Run에서 STP 전환 대기가 관찰되어, “설정 복구 = 즉시 통신 복구”로 일반화하지 않습니다.
05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Access Port는 Host Frame을 하나의 Access VLAN에 소속시킵니다.
  • Non-native VLAN은 Trunk에서 802.1Q VLAN ID로 구분됩니다.
  • 같은 Trunk를 써도 VLAN 10과 VLAN 20은 별도 Broadcast Domain입니다.
  • Native VLAN은 기본 Cisco 동작에서 Untagged 예외가 될 수 있습니다.
  • Trunk가 Up이어도 Allowed VLAN / Access VLAN 설정 때문에 특정 VLAN만 실패할 수 있습니다.
