01 · GOAL

학습 목표

설명할 수 있어야 하는 것

  • ARP가 필요한 이유
  • ARP Request가 Broadcast인 이유
  • 같은 Subnet과 다른 Subnet 통신의 차이
  • Destination IP와 Destination MAC의 차이
  • Default Gateway가 필요한 이유
  • Switch와 Router의 Forwarding 기준 차이

실습 후 답할 질문

  • 다른 Subnet으로 갈 때 Destination IP가 Gateway IP로 바뀌는가?
  • 왜 PC는 최종 목적지 MAC이 아니라 Gateway MAC을 찾는가?
  • ARP Cache를 삭제하면 첫 Packet 전에 무엇이 발생하는가?
  • Gateway가 틀리면 Wireshark에서 어떤 증거가 보이는가?
02 · LAB DESIGN

실험 구성

PC1 192.168.10.10/24 GW 192.168.10.1 │ SW1 │ R1 192.168.10.1/24 │ R1 192.168.20.1/24 │ SW2 │ PC2 192.168.20.10/24

정상 동작 테스트

  • 같은 Subnet 통신 전후 ARP Cache 비교
  • 다른 Subnet Ping 전 Gateway ARP 확인
  • ARP Cache 삭제 후 Packet 순서 캡처
  • MAC Table과 실제 Ethernet Destination 비교

관찰할 명령·패킷

  • arp -a
  • ping
  • show mac-address-table
  • ARP Request / ARP Reply
  • ICMP Echo Request / Reply
  • Ethernet Src/Dst MAC과 IP Src/Dst 비교
03 · BREAK & TROUBLESHOOT

의도적으로 만들 장애

Fault 1

Wrong Default Gateway

존재하지 않거나 잘못된 Gateway를 설정하고 ARP/ICMP 증상을 확인합니다.

Fault 2

Wrong Subnet Mask

같은 IP를 Local로 볼지 Gateway로 보낼지 판단이 어떻게 달라지는지 확인합니다.

Fault 3

Gateway Interface Down

ARP 요청과 응답 부재, 통신 실패의 관계를 확인합니다.
