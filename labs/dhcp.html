10 · 1단계 CONCEPT GUIDE

DHCP / DHCP Relay

단말이 네트워크 설정을 자동으로 받고, 서버가 멀리 있으면 중계가 필요한 이유를 설명합니다.

앞선 학습 · LACP / Link Aggregation까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

새 컴퓨터는 사용할 주소와 출구 정보를 어디서 받을까요?

30초 핵심 · DHCP는 주소와 필요한 설정을 일정 기간 사용하도록 정해 주는 절차입니다. 서버가 다른 네트워크에 있으면 중계 기능이 단말의 요청을 전달합니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

Client / Lease
설정을 요청하는 단말이 Client입니다. 주소 등을 정해진 기간 사용하는 임대 상태를 Lease라고 합니다.
Relay · 중계
단말 쪽 DHCP 메시지를 다른 네트워크의 서버에 전달하는 기능입니다.
Option · 추가 설정
주소 외에 Mask, Gateway, DNS 주소, 임대 시간 등을 함께 전할 수 있습니다. DNS의 역할은 다음 학습에서 배웁니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. Discover: 단말이 사용할 주소와 서버를 찾습니다.
  2. Offer: 서버가 주소와 설정을 제안합니다.
  3. Request: 단말이 사용할 제안을 요청합니다.
  4. ACK: 서버가 확정하면 단말이 설정을 적용합니다. 네 이름의 앞 글자를 DORA라고 합니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
주소를 받음DHCP 설정 교환이 완료됐다는 뜻입니다.
다른 네트워크 통신 성공Gateway 등 받은 설정과 실제 전달 경로도 맞아야 합니다.

05 · 복습

꼭 기억할 세 가지

  • DHCP는 IP 주소와 네트워크 설정을 함께 전달합니다.
  • 초기 임대는 찾기 → 제안 → 요청 → 확정으로 이해합니다.
  • 주소를 받았다고 모든 통신이 보장되지는 않습니다.

내 말로 설명하기

IP 주소는 받았는데 Gateway 값이 잘못됐다면 같은 네트워크와 다른 네트워크 통신은 어떻게 다를까요?

1단계 · CONCEPT GUIDE

DHCP / DHCP Relay

목표는 하나입니다. Client가 DORA로 Lease와 Network Option을 받고, Remote DHCP Server를 사용할 때 Relay가 어디에서 무엇을 바꾸는지 설명할 수 있으면 됩니다.

“IP를 받았는가?”와 “실제 통신이 되는가?”를 분리해서 봅니다.주소 할당 과정과 Gateway/DNS 같은 사용 조건은 같은 DHCP 안에서도 서로 다른 판단입니다.
1 · 개념서2 · Interactive Lab
Discover로 찾고 → Offer를 받고 → Request로 선택하고 → ACK로 Lease를 확정합니다.

Remote Server라면 Relay가 giaddr로 Client Subnet을 알려 줍니다.

00 · 30초 핵심

DHCP는 IP 하나가 아니라 “사용할 네트워크 설정”을 Lease로 합의합니다.

① Discover: IP가 없는 Client가 DHCP Server를 찾기 위해 Local Broadcast를 보냅니다.

② Relay: Server가 다른 Subnet이면 Router의 Relay가 Request를 Server까지 전달하고 giaddr로 Client Subnet을 알려 줍니다.

③ ACK: Address뿐 아니라 Mask, Default Gateway, DNS, Lease Time 같은 Option도 함께 받을 수 있습니다.

④ 검증: Lease 성공과 Remote Connectivity 성공은 같은 뜻이 아닙니다. Option이 틀리면 IP는 받아도 통신은 실패할 수 있습니다.

01 · DORA

초기 Lease는 네 메시지로 이해하면 됩니다.

D

Discover

“사용할 DHCP Server와 주소가 있나요?” Client가 먼저 찾습니다.

O

Offer

Server가 사용할 수 있는 주소와 Parameter를 제시합니다.

R

Request

Client가 사용할 Server/주소를 선택해 요청합니다.

A

ACK

Server가 Lease와 Option을 확정하고 Client가 설정을 적용합니다.

실제 검증: 동일 Transaction을 xid 0x57370148과 Client MAC으로 추적했고 최종 Lease는 192.0.2.100/24였습니다.
02 · DHCP RELAY

Broadcast를 “그냥 Routing”하는 것이 아닙니다.

CLIENT VLAN

Discover는 Broadcast

Client는 0.0.0.0 → 255.255.255.255, UDP 68→67로 시작했습니다. 이 단계의 giaddr는 0.0.0.0입니다.

ROUTED TRANSIT

Relay가 Server로 전달

R1은 같은 Transaction을 R2로 전달하면서 giaddr=192.0.2.1, hops=1로 만들었습니다. Server는 이 값을 보고 192.0.2.0/24 Pool을 선택했습니다.

헷갈리지 마세요: giaddr는 Relay/Server가 Client Subnet과 Reply 경로를 판단하는 DHCP Field이고, Option 3 Default Router는 Client가 이후 Remote Traffic에 사용할 Gateway입니다.
03 · ACK OPTIONS

Address를 받는 것과 “올바른 설정”을 받는 것은 별개입니다.

Option 1 · Mask255.255.255.0
Option 3 · Router192.0.2.1
Option 6 · DNS203.0.113.53
Option 51 · Lease3600 seconds
이번 검증에서 ACK가 위 네 값을 전달했고 Client는 Address/Mask/Gateway를 적용했습니다. DNS는 Option 전달값만 검증했으며 실제 DNS Server 응답은 이번 학습 범위가 아닙니다.
04 · 세 가지 장애를 위치로 구분

Client 화면이 비슷해도 Packet이 마지막으로 보이는 곳이 다릅니다.

SERVER DOWN

Discover는 Server Segment까지 도착

Relay와 Route는 정상이라 CP3까지 Discover가 보였지만 Server가 Offer/ACK를 만들지 않아 신규 Lease가 실패했습니다.

Client Discover ✓ → Relay ✓ → Server Segment ✓ → Offer ✕
RELAY MISSING

Discover가 Client VLAN에서 멈춤

ip helper-address를 제거하자 Client Broadcast는 CP1/CP2에 있었지만 CP3에는 해당 DHCP Transaction이 없었습니다.

Client Discover ✓ → Relay ✕ → Server Segment DHCP ✕
WRONG ROUTER OPTION

DORA는 성공, Remote 통신은 실패

Option 3만 192.0.2.254로 바꾸자 Lease는 정상 완료됐지만 Client는 존재하지 않는 Gateway를 ARP하다 Remote Ping에 실패했습니다.

DORA ✓ · Lease ✓ · Gateway Option ✕ · Remote Connectivity ✕
05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • 초기 DHCP는 Discover → Offer → Request → ACK로 이해합니다.
  • Remote DHCP Server를 쓰려면 Relay가 Client Broadcast를 Server에 전달해야 합니다.
  • giaddr와 Option 3 Default Router는 목적이 다른 값입니다.
  • ACK는 Address 외에 Mask / Gateway / DNS / Lease도 전달할 수 있습니다.
  • Lease 성공 ≠ 실제 Remote 통신 성공입니다.
내 말로 설명하기

“Client가 DHCP Server와 다른 Subnet에 있을 때 Discover가 어떻게 Server까지 가는가?”

Broadcast, Relay, giaddr, ACK라는 네 단어를 사용해 설명할 수 있다면 충분합니다.
