22 · 1단계 CONCEPT GUIDE

VRF

먼저 사용할 경로표를 고르고 그 표 안에서 목적지 경로를 찾는 원리를 설명합니다.

앞선 학습 · First-Hop Redundancy / FHRP까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

목적지 IP가 똑같아도 한 라우터에서 서로 다른 곳으로 보낼 수 있을까요?

30초 핵심 · VRF는 한 라우터 안의 라우팅 공간을 분리합니다. 같은 목적지 IP라도 BLUE 표와 RED 표에서 찾으면 서로 다른 경로를 선택할 수 있습니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

VRF / Context
독립된 라우팅·전달 공간과 지금 어느 공간에서 판단하는지를 뜻합니다.
Interface Membership
인터페이스가 어느 VRF에 속하는지입니다. 연결 경로도 해당 공간의 표에 나타납니다.
Route Leak
분리된 공간 사이에 선택한 경로 정보를 명시적으로 공유하는 것입니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 패킷이 어느 VRF에 속하는지 확인합니다.
  2. 그 VRF의 경로표에서 목적지를 찾습니다.
  3. 선택된 경로의 인터페이스나 다음 라우터로 보냅니다.
  4. 공유 설정이 없다면 다른 VRF의 경로를 자동으로 함께 사용하지 않습니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
같은 IP · 같은 공간하나의 경로 판단 맥락 안에서 해석합니다.
같은 IP · 다른 VRF분리된 공간의 다른 대상을 나타낼 수 있습니다.

05 · 복습

꼭 기억할 세 가지

  • 목적지보다 먼저 어느 경로표를 쓰는지 봅니다.
  • 분리된 VRF에는 겹치는 주소가 공존할 수 있습니다.
  • 경로 공유와 왕복 통신 성공은 다릅니다. 돌아오는 경로도 필요합니다.

1단계 · CONCEPT GUIDE

VRF

같은 Router 안에서도 Routing Table을 여러 개로 분리할 수 있습니다. 이번 주제의 목표는 목적지 IP만 보지 않고, 먼저 어느 VRF Context에서 Route Lookup을 하는가를 판단하는 습관을 만드는 것입니다.

VRF Context → 그 VRF의 Routing Table → 출력 경로

Destination IP가 같아도 Context가 다르면 다른 Interface로 전달될 수 있습니다.

02 · NORMAL FLOW

VRF Forwarding은 네 단계로 기억하세요.

1

Context 확인

Packet이나 VRF-aware test가 어느 VRF에 속하는지 먼저 결정합니다.

2

해당 Table Lookup

Global 전체가 아니라 선택된 VRF Routing Table에서 목적지 Route를 찾습니다.

3

출력 경로 선택

그 Table의 Connected/Static Route가 가리키는 Interface 또는 Next Hop을 사용합니다.

4

다른 VRF는 그대로 분리

명시적으로 Route를 공유하지 않았다면 다른 VRF의 Route는 자동으로 후보가 되지 않습니다.

04 · ISOLATION / ROUTE LEAK

기본은 격리, 공유는 명시적으로 합니다.

BEFORE LEAK

BLUE에는 Global Route가 없습니다.

192.0.2.0/24BLUE Table에 없음
BLUE → 192.0.2.10출력 없음
→
EXPLICIT LEAK

선택한 /24만 BLUE에 추가

192.0.2.0/24Static Route 추가
BLUE → GlobalRequest 3개 전달

Route Leak은 왕복 통신 보장이 아닙니다.

이번 Run은 BLUE→Global 방향만 Leak했습니다. CP-GLOBAL에는 Echo Request 3개와 PC-GLOBAL이 보낸 Echo Reply 3개가 모두 보였지만, Global Table에 BLUE source 10.20.20.1로 돌아갈 Route가 없어 원래 BLUE Ping은 0/3이었습니다. 링크에서 Reply를 봤다는 것과 원래 VRF Context까지 Reply가 전달됐다는 것은 다릅니다.

Recovery: 정적 Leak Route를 제거하자 BLUE Table에서 192.0.2.0/24가 다시 사라졌고, BLUE/RED/Global 최종 대조 통신은 각각 3/3으로 Baseline을 회복했습니다.
05 · REVIEW

이 다섯 문장을 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • VRF는 하나의 Router 안에서 Routing/Forwarding Context를 분리합니다.
  • Interface가 어느 VRF에 속하느냐에 따라 Connected/Local Route가 설치되는 Table이 달라집니다.
  • 서로 다른 VRF에는 같은 Prefix와 같은 IP 주소가 공존할 수 있습니다.
  • 같은 Destination IP라도 VRF Context가 다르면 다른 Interface로 전달될 수 있습니다.
  • Route Leak은 선택 Route의 명시적 공유이며 Return Route는 별도로 확인해야 합니다.
