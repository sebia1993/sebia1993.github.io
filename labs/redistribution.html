Redistribution / Route Control

서로 다른 경로 정보 체계 사이에서 넘길 경로를 선택하는 재분배 경계를 설명합니다.

앞선 학습 · BGP / Route Policy까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

한 라우터가 두 라우팅 프로토콜을 쓰면 배운 경로가 자동으로 서로 넘어갈까요?

30초 핵심 · 프로토콜을 함께 실행하는 것만으로 경로 정보가 모두 공유되지는 않습니다. 재분배는 다른 프로토콜에서 배운 경로 중 허용한 것을 새 프로토콜에 주입하는 일입니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

Redistribution
다른 경로 출처의 정보를 대상 라우팅 프로토콜에 넣는 재분배입니다.
Route Tag
정책이 경로를 식별할 때 참고하는 관리용 표식입니다. 경로 비용과는 다른 값입니다.
Metric / AD
Metric은 프로토콜 내부의 경로 평가값입니다. AD는 이 Cisco 예제에서 같은 범위의 여러 경로 출처 중 설치할 것을 고르는 선호값입니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 어떤 출처에서 배운 경로인지 확인합니다.
  2. 두 프로토콜의 경계에서 재분배 설정을 확인합니다.
  3. 주소 범위나 Tag로 넘길 경로를 선별합니다.
  4. 허용한 경로를 대상 프로토콜에 넣고, 상대의 경로 정보에 반영됐는지 봅니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
경로 재분배 정책어떤 경로 정보를 다른 프로토콜로 넘길지 정합니다.
패킷 필터 정책지금 지나가는 사용자 패킷을 허용할지 정합니다.

05 · 복습

꼭 기억할 세 가지

  • 같이 실행한다고 경로가 자동 공유되지는 않습니다.
  • 넘길 경로를 명시적으로 제한합니다.
  • Tag·Metric·AD는 다른 목적의 값입니다.

1단계 · CONCEPT GUIDE

Redistribution / Route Control

한 Router가 OSPF와 BGP를 둘 다 알고 있으면, OSPF 경로가 BGP로 자동 전달될까요? 아닙니다. 서로 다른 Routing Protocol 사이에서 경로 정보를 넘기려면 어떤 Route를 어느 방향으로 보낼지 명시적으로 정해야 합니다.

원래 Route → 재분배 경계 → Policy → 다른 Protocol의 Route → 최종 Routing Table(RIB) 선택

Redistribution은 Packet을 복사하거나 강제로 보내는 기능이 아니라 Routing Information을 다른 Protocol에 주입하는 라우팅 제어 영역(Control Plane)의 동작입니다.

03 · ROUTE POLICY

모든 Route를 넘기지 않고, 필요한 Route만 선별합니다.

PREFIX POLICY

주소 범위로 허용

R1은 TARGET은 BGP로 넘기지만 BLOCK은 기본적으로 넘기지 않았습니다. 임시 Permit을 추가했을 때만 BLOCK이 R3에 나타났고, 제거 후 다시 철회됐습니다.

TAG GUARD

표식으로 재유입 차단

TAGGED Route는 OSPF 안에 Tag 65002를 가지고 있었습니다. 앞선 Tag Deny가 뒤의 Prefix Permit보다 먼저 적용되어 BGP 재분배를 막았습니다.

SEQ 5Tag 65002를 가진 RouteDENY
SEQ 10TARGET PrefixPERMIT
SEQ 15TAGGED PrefixPERMIT

Route-map Filter ≠ Packet ACL

여기서 Permit/Deny는 데이터 Packet을 통과·차단하는 뜻이 아니라 어떤 Routing Information을 다른 Protocol에 주입할지 결정합니다. Tag도 Metric이나 AD가 아니라 Policy가 Match할 수 있는 행정용 표식입니다.

04 · 세 숫자의 역할

Metric, Tag, AD는 서로 다른 질문에 답합니다.

METRIC

그 Protocol 안에서 경로를 어떻게 평가할까?

이번 OSPF E1에서는 외부 seed metric과 내부 cost가 경로 metric에 반영됐습니다.

“같은 Protocol 내부 경로 계산”
ROUTE TAG

이 Route가 어디서 왔는지 표시할까?

Tag 65002를 붙이고 다음 Redistribution Boundary에서 Match해 재유입을 막았습니다.

“Policy가 읽는 표식”
ADMINISTRATIVE DISTANCE

서로 다른 Route Source 중 무엇을 RIB에 설치할까?

이번 Cisco IOL에서는 eBGP AD20과 OSPF AD110이 같은 Prefix를 제공했을 때 낮은 AD의 BGP Route가 설치됐습니다.

“Cisco의 Local Source Preference”

06 · 실제 검증에서 배운 운영 감각

Policy 변화는 즉시 한 순간에 끝난다고 가정하지 않습니다.

Withdrawal은 비동기적으로 보일 수 있습니다.

BLOCK Permit을 제거한 직후 첫 조회에는 경로가 잠시 남았고, 추가 조작 없이 settled 상태에서 철회됐습니다. 고정된 수렴 시간을 주장하지 않습니다.

Recovery를 끝까지 확인합니다.

최종 상태에서 OSPF Full, BGP Established, TARGET 존재, BLOCK/TAGGED 부재, CONFLICT는 BGP 설치, 임시 Permit은 제거된 상태까지 확인했습니다.

07 · REVIEW

이 다섯 문장을 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Routing Protocol은 서로의 Route를 자동으로 교환하지 않습니다.
  • Redistribution은 Routing Information을 다른 Protocol에 주입하는 Control-Plane 동작입니다.
  • Prefix와 Tag Policy로 넘길 Route를 제한할 수 있습니다.
  • Route Tag, Metric, Administrative Distance는 서로 다른 목적의 값입니다.
  • 같은 Prefix의 여러 Source가 있어도 RIB에는 한 Source가 설치될 수 있습니다.

Cisco · Administrative Distance

같은 Prefix가 서로 다른 Routing Source에서 올 때 Cisco RIB가 Source를 선택하는 구현 동작을 확인했습니다.

검증 범위: Cisco IOL IOS 15.4(2)T4 3대의 격리 PNETLab에서 REDIST-01~06을 CLI 163개 assertion과 내부 링크 PCAP 2개·packet assertion 57개로 PASS했습니다. 실제 지속 Routing Loop는 만들지 않았고 Tag Guard 효과만 검증했습니다. Null0 Prefix는 Route Advertisement 검증용이며 Host Service 성공을 뜻하지 않습니다. 정확한 수렴 시간도 일반화하지 않습니다.
