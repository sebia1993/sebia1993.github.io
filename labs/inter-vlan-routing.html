Inter-VLAN Routing

목표는 하나입니다. 같은 VLAN은 직접 L2로 보내고, 다른 VLAN은 Default Gateway를 거쳐 Routing된다는 차이를 Ethernet과 IP Header까지 연결해 설명할 수 있으면 됩니다.

이 페이지에서는 경계만 정확히 봅니다.Routing Table이나 CLI를 외우기보다 “Host가 누구의 MAC을 쓰는가 → L3 Switch가 무엇을 바꾸는가”에 집중합니다.
1 · 개념서2 · Interactive Lab
IP 목적지는 최종 Host, Ethernet 목적지는 현재 L2 구간의 Next-Hop입니다.

Same VLAN → Peer MAC · Different VLAN → Gateway MAC → Routing → 새 L2 Frame

00 · 30초 핵심

먼저 “같은 Subnet인가?”를 판단합니다.

① Same VLAN: 목적지가 on-link라면 최종 Host를 ARP하고 그 Host MAC으로 직접 보냅니다.

② Different VLAN: 목적지가 off-link라면 Default Gateway를 ARP하고 Gateway MAC으로 보냅니다.

③ L3 Switch: IP Destination은 그대로 두고 TTL을 감소시킨 뒤 다른 VLAN에 맞는 새 Ethernet Header로 전송합니다.

④ Reply: 반대편 Host도 똑같이 독립 판단합니다. Return Path 역시 자기 Gateway를 사용합니다.

01 · SAME VLAN vs DIFFERENT VLAN

달라지는 것은 “현재 L2 목적지”입니다.

PC10A → PC10B

같은 VLAN 10

PC10A는 10.10.10.20을 직접 ARP하고, Ethernet Destination을 PC10B MAC으로 보냅니다. Gateway는 이 Flow의 Next-Hop이 아닙니다.

PC10A → PC20A

다른 VLAN 20

PC10A는 Remote Host가 아니라 Gateway 10.10.10.1을 ARP합니다. Ethernet Destination은 Gateway MAC이지만 IP Destination은 여전히 10.10.20.10입니다.

02 · SVI ROUTING

L3 Switch를 지나면 Ethernet Header는 새로 만들어집니다.

이번 실제 검증에서 동일 Echo Request를 VLAN10과 VLAN20 링크에서 대조했습니다.

PC10AVLAN10 · TTL 64
→ Gateway MACIP dst = PC20A
SW1 SVIRoute Lookup · TTL -1
→ PC20A MAC새 Ethernet Header
PC20AVLAN20 · TTL 63

VLAN10에서 들어올 때

IP 10.10.10.10 → 10.10.20.10 MAC PC10A → VLAN10 Gateway TTL 64

VLAN20으로 나갈 때

IP 10.10.10.10 → 10.10.20.10 MAC VLAN20 L3 Interface → PC20A TTL 63
이번 IOL 특징: Vlan10과 Vlan20 SVI의 숫자 MAC은 둘 다 aa:bb:cc:80:01:00으로 같았습니다. 중요한 것은 “두 SVI MAC 값이 다르냐”가 아니라, Ingress Frame을 그대로 전달하지 않고 Egress Next-Hop에 맞는 L2 Header를 새로 구성했다는 점입니다.
03 · REPLY PATH

Reply도 독립적으로 Gateway를 선택합니다.

1

PC20A가 Reply 준비

Destination은 PC10A 10.10.10.10입니다.

2

Off-link 판단

PC20A는 PC10A가 VLAN20 밖에 있다고 판단합니다.

3

Gateway 사용

VLAN20 Gateway 10.10.20.1의 MAC으로 Reply Frame을 보냅니다.

4

SW1 Routing

TTL 64 → 63으로 감소하고 VLAN10으로 전달합니다.

5

PC10A 도착

VLAN10 Egress Ethernet Destination은 PC10A MAC입니다.

04 · 두 가지 대표 장애

같은 VLAN과 다른 VLAN을 나눠 보면 원인이 빨리 보입니다.

SVI DOWN

Vlan20 L3 Interface만 shutdown

10.10.20.0/24 Connected Route가 사라지고 Inter-VLAN Ping은 실패했습니다. 하지만 PC20A↔PC20B 같은 VLAN20 L2 통신은 3/3 정상으로 유지됐습니다.

VLAN20 내부 L2 ✓ · VLAN10 ↔ VLAN20 Routing ✕
WRONG GATEWAY

PC10A Gateway만 10.10.10.254

PC10A↔PC10B 같은 VLAN 통신은 계속 성공했지만 Remote VLAN은 존재하지 않는 Gateway에 ARP만 반복하고 실제 Remote Echo Frame을 만들지 못했습니다.

Same VLAN ✓ · Gateway ARP 10.10.10.254 응답 없음 → Remote ✕
복구 주의: Vlan20을 다시 올린 직후 첫 Run은 2/3이었고, ARP가 다시 형성된 뒤 별도 확인 Run에서 3/3이 됐습니다. 그래서 “SVI no shutdown 즉시 완벽 복구”라고 일반화하지 않습니다.
05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Same VLAN이면 Peer MAC으로 직접 보냅니다.
  • Different VLAN이면 Gateway MAC으로 보내지만 IP Destination은 최종 Host입니다.
  • L3 Routing을 거치면 TTL이 감소하고 Ethernet Header는 Egress용으로 새로 구성됩니다.
  • Reply Path도 독립적으로 자기 Default Gateway를 사용합니다.
  • Same-VLAN이 된다고 해서 Gateway / SVI가 정상이라는 뜻은 아닙니다.
