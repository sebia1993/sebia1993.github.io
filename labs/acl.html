1단계 · CONCEPT GUIDE

ACL

목표는 하나입니다. 패킷의 Source/Destination/Protocol/Port와 ACL이 적용된 Interface/Direction을 보고 Permit/Deny 결과와 Packet Stop 지점을 설명할 수 있으면 됩니다.

Route가 정상이라고 Packet이 반드시 통과하는 것은 아닙니다.R2에서 ACL이 Match하면 Routing은 그대로여도 특정 Packet만 멈출 수 있습니다.
1 · 개념서2 · Interactive Lab
Interface / Direction → Top-down ACE → First Match → Permit or Deny → Implicit Deny

ACL은 세션을 추측하는 것이 아니라 현재 Packet Header를 평가합니다.

00 · 30초 핵심

ACL은 “어디서, 어느 방향으로, 어떤 Packet이 첫 Match했는가”를 봅니다.

1

Direction

Packet이 ACL이 적용된 Interface의 in/out을 실제로 통과하는지 확인합니다.

2

Match

Source, Destination, Protocol, TCP/UDP Port 같은 조건을 비교합니다.

3

Top-down

ACE를 위에서 아래로 검사합니다.

4

First Match

처음 Match한 Permit/Deny에서 판단이 끝납니다.

5

Implicit Deny

끝까지 Match하지 않으면 마지막에 보이지 않는 Deny가 있다고 생각합니다.

01 · POLICY POINT

이번 Lab은 R2만 Policy Enforcement Point입니다.

R2 · POLICY ENFORCEMENT CP12CP23
R110.0.12.1
Source/Test
R2E0/0 ← R1
E0/1 → R3
R310.0.23.2
Destination/Test
검증 설계: Routing과 Interface 상태는 고정하고 R2 ACL만 바꿨습니다. 그래서 Packet이 CP12에는 있는데 CP23에는 없으면 R2 정책에서 Stop된 것으로 분리할 수 있습니다.
02 · EXTENDED ACL MATCH

같은 두 Router 사이에서도 Protocol과 Port에 따라 결과를 다르게 만들 수 있습니다.

SOURCE

10.0.12.1

어디서 출발한 Packet인지 Match합니다.

DESTINATION

10.0.23.2

어디로 가는 Packet인지 Match합니다.

PROTOCOL

ICMP / TCP

같은 주소라도 ICMP만 막고 TCP는 허용할 수 있습니다.

PORT

TCP dst 23

TCP 중에서도 목적지 Port 23만 차단할 수 있습니다.

ACL-01 ACTUAL

ICMP Stop · TCP/23 Permit

R1→R3 ICMP만 Deny하자 Ping은 0/3, TCP/23은 실제 SYN/SYN-ACK/ACK와 R3 VTY prompt까지 도달했습니다.

ICMP: R1 → CP12 → R2 STOP
TCP/23: R1 → CP12 → R2 → CP23 → R3
ACL-02 ACTUAL

TCP/23 Stop · ICMP Permit

TCP destination Port 23만 Deny하자 Ping은 3/3, TCP SYN은 CP12에만 있고 CP23에는 없었습니다.

ICMP: R1 ↔ R2 ↔ R3
TCP/23: R1 → CP12 → R2 STOP
03 · TOP-DOWN / FIRST MATCH

같은 ACE도 순서를 바꾸면 결과가 바뀝니다.

SPECIFIC PERMIT FIRST

TCP/23은 위에서 먼저 Permit

10permit tcp ... eq 23TCP/23 FIRST MATCH
20deny ip R1 → R3ICMP 등 Broad Deny
30permit ip any any나머지
BROAD DENY FIRST

TCP/23도 아래 Permit까지 못 갑니다.

10deny ip R1 → R3TCP/23 FIRST MATCH
20permit tcp ... eq 23이번 Packet hit +0
30permit ip any any나머지
실제 검증: Broad Deny를 위로 올리자 TCP/23도 차단됐고, 아래 Specific Permit의 hit는 증가하지 않았습니다. First Match 이후에는 다음 ACE가 결과를 뒤집지 않습니다.
04 · IMPLICIT DENY

“Deny를 안 적었다”와 “허용된다”는 같은 뜻이 아닙니다.

EXPLICIT

ICMP Permit 한 줄

R1→R3 ICMP Permit만 명시하자 Ping은 3/3으로 정상 통과했습니다.

10 permit icmp R1 → R3
UNMATCHED

TCP/23은 Implicit Deny

TCP/23 명시적 Deny가 없는데도 SYN은 CP12에만 보이고 CP23에는 없었습니다. 어떤 ACE에도 Match하지 않았기 때문입니다.

TCP/23 → no ACE match → implicit deny → R2 STOP
05 · INTERFACE / DIRECTION

ACL 내용이 같아도 적용 방향이 틀리면 원하는 Packet을 보지 못합니다.

WRONG DIRECTION

R2 E0/0 OUT

R1→R3 Request는 E0/0으로 들어오므로 E0/0 outbound ACL을 통과하지 않습니다. Ping 3/3, Deny ACE hit 0이었습니다.

R1 → [E0/0 IN] R2 → E0/1 → R3
CORRECT DIRECTION

R2 E0/0 IN

같은 ACL을 inbound로 옮기자 Request가 실제 ACL을 통과하면서 R2에서 차단됐고 Deny hit가 3 증가했습니다.

R1 → CP12 → [E0/0 IN ACL] R2 STOP
06 · PACKET DIRECTION vs PING DIRECTION

ACL-06에서 가장 중요한 오개념이 실제 검증으로 드러났습니다.

ORIGINAL EXPECTED · FAIL PRESERVED

모든 ICMP를 R1→R3로 Deny하면 “R3→R1 Ping 성공”이 아닙니다.

원래 정책 deny icmp R1 R3은 R1이 시작하는 Echo Request뿐 아니라, R3가 시작한 Ping에 대해 R1이 보내는 Echo Reply도 R1→R3 방향 ICMP이므로 차단했습니다. 실제로 Reverse Request는 R1까지 도착했지만 Reply가 R2에서 Stop되어 Reverse Ping도 0/3이었습니다.

CORRECTED ONE-WAY

Echo Request만 Deny

deny icmp R1 R3 echo로 한정하자 R1→R3 Ping은 0/3, R3→R1 Ping은 3/3이 실제로 성립했습니다.

R1 Echo Request → R2 STOP
R3 Echo Request → R1 → Echo Reply → R3 ✓
BIDIRECTIONAL

양쪽 ingress에서 Echo Request Deny

R2 E0/0 inbound와 E0/1 inbound에 방향별 Echo Request Deny를 넣자 양쪽 Ping이 모두 0/3이었고, ACL 제거 후 다시 양방향 3/3으로 복구됐습니다.

R1 Echo Request → R2 STOP
R3 Echo Request → R2 STOP
핵심: ACL은 Stateful Firewall이 아닙니다. “통신 방향”을 기억하는 것이 아니라 각 Packet의 Header를 독립적으로 평가합니다.
07 · REVIEW

여기까지만 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Extended ACL은 Source/Destination/Protocol/Port를 조건으로 사용할 수 있습니다.
  • ACE는 위에서 아래로 보고 첫 Match에서 판단이 끝납니다.
  • 끝까지 Match하지 않으면 Implicit Deny입니다.
  • ACL은 적용된 Interface와 in/out Direction을 실제 Packet이 지나야 합니다.
  • ACL은 Stateless이므로 Ping Request와 Reply를 각각 별도 Packet으로 생각합니다.
내 말로 설명하기

“Route는 정상인데 R1→R3 Ping만 실패한다면 ACL에서 무엇을 볼까?”

Interface, Direction, ACE Order, First Match, Protocol/Port, Implicit Deny라는 단어를 사용해 설명할 수 있다면 충분합니다.
