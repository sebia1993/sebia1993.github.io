1단계 · CONCEPT GUIDE

First-Hop Redundancy / FHRP

Host는 같은 Virtual Gateway를 계속 사용하고, 실제 Forwarding 책임을 가진 Router만 바뀔 수 있습니다. 먼저 Virtual Router / VIP / Virtual MAC / Forwarding Owner라는 공통 Mental Model을 만든 뒤, VRRP의 Active/Backup과 HSRP의 Active/Standby 용어를 구현별로 구분합니다.

같은 Virtual Gateway, 바뀌는 Forwarding Owner

Host → Virtual Router(IP/MAC) → 현재 Forwarding Owner → Upstream

00 · 30초 핵심

Host는 Router 두 대를 직접 고르는 것이 아닙니다.

WITHOUT FHRP

Default Gateway 한 대에 장애가 나면?

Host 설정에 등록된 Gateway가 그 물리 Router 하나라면, 그 Router의 장애를 다른 Router가 자동으로 대신하기 어렵습니다.

WITH FHRP

Host는 Virtual Gateway만 바라봅니다.

Router들이 하나의 Virtual IP/MAC을 공유하고, 현재 역할을 가진 Router가 실제 패킷을 전달합니다.

검증된 핵심: HSRP 정상 상태에서 PC1의 Gateway는 10.10.10.1, ARP는 HSRP Virtual MAC으로 해석됐고 실제 Echo Request는 R1 uplink로 전달됐습니다.
01 · NORMAL FLOW

정상 상태는 네 단계로 기억하면 충분합니다.

1

Gateway는 VIP

Host의 Default Gateway 설정은 물리 R1/R2 주소가 아니라 Virtual IP입니다.

2

ARP는 Virtual MAC

Host는 VIP를 FHRP가 제공하는 Virtual MAC으로 해석합니다.

3

한 Router가 Owner

HSRP는 Active, VRRP는 Master가 현재 Forwarding 역할을 가집니다.

4

Peer를 계속 감시

Hello/Advertisement와 상태 정보를 바탕으로 역할 변경 조건을 판단합니다.

02 · PRIORITY / PREEMPT / TRACKING

세 설정은 역할이 서로 다릅니다.

PRIORITY

누가 더 선호되는가?

이번 HSRP Lab에서 R1=110, R2=100으로 두었고 안정 상태에서 R1이 Active가 됐습니다.

PREEMPT

더 좋은 Router가 돌아오면 되찾는가?

R1 복구 후 priority 110과 preempt가 유지된 상태에서 R1이 다시 Active가 되는 것을 확인했습니다.

TRACKING

LAN이 살아 있어도 upstream은 죽을 수 있습니다.

R1의 client-facing LAN은 Up인 채 upstream만 Down시켜 priority를 110→90으로 낮추자 R2가 Active를 가져갔습니다.

IMPORTANT

역할 전환 = 무손실 보장은 아닙니다.

Tracking 전환·복구 구간에서는 일시적 Timeout/ICMP 오류가 관측됐습니다. FHRP는 장애 전환 메커니즘이지 무손실을 보장하는 문장이 아닙니다.

05 · REVIEW

이 다섯 문장을 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Host는 물리 Router가 아니라 Virtual IP를 Default Gateway로 사용합니다.
  • ARP는 Virtual IP를 Virtual MAC으로 해석합니다.
  • 장애 시 Host 설정은 그대로이고 Forwarding Owner가 바뀔 수 있습니다.
  • Priority는 선호도, Preemption은 복구 후 역할 재탈환, Tracking은 경로 상태를 Priority에 반영합니다.
  • VRRP는 표준 프로토콜이고 HSRP는 Cisco 구현입니다. 둘은 Virtual-Gateway Mental Model을 공유하지만 역할명과 Control Protocol은 다릅니다.
