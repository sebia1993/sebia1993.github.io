12 · 1단계 CONCEPT GUIDE

Routing Table / Static / Default Route

목적지에 맞는 경로 중 가장 구체적인 주소 범위를 고르는 원리를 설명합니다.

앞선 학습 · DNS까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

목적지로 갈 수 있는 길이 여러 개 적혀 있으면 어느 길을 고를까요?

30초 핵심 · 라우터는 목적지 IP를 경로표와 비교합니다. 맞는 경로가 여러 개면 더 구체적인 범위, 즉 Prefix Length가 긴 경로를 선택합니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

Routing Table / Route
경로 정보가 모인 표와 그 개별 항목입니다. 항목은 목적지 범위와 전달 방향을 알려줍니다.
Connected / Static
직접 연결된 네트워크의 경로가 Connected, 관리자가 지정한 경로가 Static입니다.
Default / LPM
Default Route인 0.0.0.0/0은 더 구체적인 경로가 없을 때 사용합니다. 가장 긴 Prefix Length를 고르는 규칙은 LPM입니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. 목적지 IP를 확인합니다.
  2. 경로표에서 목적지에 일치하는 주소 범위를 찾습니다.
  3. 여러 범위가 맞으면 Prefix Length가 가장 긴 경로를 고릅니다.
  4. 선택한 경로의 다음 라우터나 출력 인터페이스로 보냅니다. 사용 가능한 경로가 없으면 전달할 수 없습니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
203.0.113.0/24해당 /24 범위의 목적지를 구체적으로 지정합니다.
0.0.0.0/0모든 IPv4 목적지에 맞지만 더 구체적인 경로가 있으면 밀립니다.

05 · 복습

꼭 기억할 세 가지

  • 경로 선택의 기준은 목적지 IP입니다.
  • 길이가 다른 일치 범위 중 가장 구체적인 경로를 고릅니다.
  • 기본 경로도 설정·사용 가능한 경로가 있어야 쓸 수 있습니다.

1단계 · CONCEPT GUIDE

Routing Table / Static / Default Route

목표는 하나입니다. 목적지 IP를 보고 어떤 Route가 선택되며, 그 결과 패킷이 어느 Next Hop으로 전달되는지 설명할 수 있으면 됩니다.

라우터는 “가장 가까워 보이는 길”이 아니라 Routing Table에서 가장 구체적으로 일치하는 Prefix를 선택합니다.선택된 Route가 Next Hop / Output Interface를 결정합니다.
1 · 개념서2 · Interactive Lab
Destination IP → Matching Prefix → Longest Prefix Match → Next Hop / Output Interface → Forward

더 구체적인 Route가 없을 때만 Default Route가 마지막 선택지가 됩니다.

00 · 30초 핵심

Route 선택은 “목적지 IP와 Prefix의 일치 정도”부터 봅니다.

① Connected: 활성 L3 Interface가 직접 연결한 Network는 Connected Route로 보입니다.

② Static: 관리자가 특정 Prefix의 Next Hop을 직접 지정할 수 있습니다.

③ Default: 0.0.0.0/0은 더 구체적인 일치 Route가 없을 때 사용하는 마지막 Route입니다.

④ Longest Prefix Match: 여러 Route가 동시에 일치하면 Prefix Length가 가장 긴 Route가 우선입니다.

01 · ROUTE TYPES

이번 Lab에서는 세 종류만 구분하면 충분합니다.

CONNECTED

직접 연결 Network

R1의 Interface가 up/up이면 그 Interface Prefix가 Routing Table에 Connected로 나타났습니다.

C 10.10.10.0/24
C 192.0.2.0/30
C 192.0.2.4/30
STATIC

특정 Prefix → R2

203.0.113.0/24는 R2 방향 Next Hop 192.0.2.2로 지정했고 실제 패킷도 CP2에서 확인됐습니다.

S 203.0.113.0/24
via 192.0.2.2
DEFAULT

그 외 목적지 → R3

R1에 더 구체적인 Route가 없는 198.51.100.10은 Default Route를 사용해 R3 방향 CP3로 전달됐습니다.

S* 0.0.0.0/0
via 192.0.2.6
02 · PATH

Routing Table의 선택 결과가 실제 패킷 경로로 이어집니다.

PC110.10.10.10/24
GW 10.10.10.1
R1Route Decision Point
/24 → R2 · /0 → R3
R2Specific Route Next Hop
203.0.113.10/32
R3Default Route Next Hop
198.51.100.10/32
실제 검증: Static 대상은 CP2(R1↔R2), Default 대상은 CP3(R1↔R3)에서 각각 3개의 Echo Request/Reply 쌍이 확인됐고, 비선택 경로에는 대응 Echo가 없었습니다.
03 · LONGEST PREFIX MATCH

203.0.113.10은 /24와 /0에 모두 일치하지만 /24가 이깁니다.

203.0.113.0/2424 bit match→ R2 · 선택
0.0.0.0/00 bit match→ R3 · 후보지만 미선택
선택 기준

Prefix Length가 더 긴 Route

/24는 /0보다 목적지를 더 구체적으로 설명합니다. 그래서 Default Route가 존재해도 /24 Static Route가 먼저 선택됩니다.

이번 검증

CP2 3쌍 · CP3 대응 Echo 0

Routing Table의 선택과 실제 패킷 경로가 일치했습니다. 이 실험은 서로 다른 Prefix Length의 LPM을 검증한 것이며 AD/Metric 비교 실험은 아닙니다.

04 · NO ROUTE / RECOVERY

Default Route가 사라지면 R1에서 더 이상 다음 Hop을 선택할 수 없습니다.

FAILURE · R1 E0/2 DOWN

Connected + Default Route 제거

R3 방향 Interface를 내리자 192.0.2.4/30 Connected Route와 그 Next Hop에 의존한 Default Static Route가 Routing Table에서 사라졌습니다.

CP1 요청 3개 → R1 · CP2 전달 0 · CP3 전달 0
RECOVERY · E0/2 UP

Route 재설치 + 통신 복구

Interface를 복구하자 Connected Route와 Default Route가 다시 설치됐고 R3 방향 Ping도 3/3으로 복구됐습니다.

Route 복원 → CP3 Request/Reply 재확인 → Final Baseline 복원
05 · STANDARD vs IMPLEMENTATION

No Route의 ICMP Code는 표준과 이번 Cisco 실제값을 구분합니다.

RFC 1812

Type 3 · Code 0

No Route(기본 경로도 없음) 상황에서 표준은 ICMP Destination Unreachable의 Network Unreachable(Code 0)을 요구합니다.

이번 CISCO IOL 15.4(2)T4

Type 3 · Code 1

실제 장애 시험 3개와 추가 재검증 6개에서 모두 Host Unreachable(Code 1)이 관측됐습니다. 이 값을 모든 Cisco 버전의 공통 동작으로 일반화하지 않습니다.

중요: 이번 학습의 핵심 불변식은 “사용 가능한 Route가 없으면 R1에서 패킷이 다음 경로로 Forward되지 않는다”입니다. ICMP Code 차이는 표준과 구현의 차이로 별도 기록합니다.
06 · REVIEW

여기까지만 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Route 선택은 Destination IP 기준입니다.
  • 여러 Route가 맞으면 Longest Prefix Match로 가장 구체적인 Prefix를 선택합니다.
  • Default Route는 마지막 후보이며, 더 구체적인 Route가 있으면 밀립니다.
  • 선택된 Route의 Next Hop / Output Interface가 실제 전달 방향을 정합니다.
  • Route가 사라지면 패킷이 멈추며, 표준과 Vendor의 ICMP 세부 구현은 구분할 수 있습니다.
