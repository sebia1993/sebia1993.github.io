원격 통신에서는 PC1만 ARP하는 것이 아닙니다. R2도 선택한 출력 링크에서 최종 Host 또는 다음 홉의 MAC을 알아야 Ethernet Frame을 만들 수 있습니다.

Simulator 단순화: ARP/Neighbor cache의 실제 aging timer와 REACHABLE/STALE 같은 상태 전이는 모델링하지 않습니다. Cache는 관련 설정 변경, 실습 초기화 또는 명시적 clear 명령 전까지 유지됩니다.

고급 실습 · 장비 설정 / 터미널 토폴로지 설정과 완전히 연동
토폴로지에서 장비를 클릭해 설정하거나 아래 빠른 장비 버튼을 사용하세요. 변경값은 다음 PING의 on-link 판단·ARP·next-hop·Connected Route·Reply 방향 Neighbor Resolution에 반영됩니다. 지원 범위: IPv4/Ethernet과 R2의 Connected Route를 모델링합니다. 이 Lab에서 LAN A와 LAN B는 각각 하나의 Ethernet L2 Broadcast Domain이며 VLAN은 사용하지 않습니다. PC1/PC2/PC3는 IP forwarding을 하지 않는 End Host입니다. Switch는 ARP Broadcast Flooding과 필요한 Frame 경로만 시각화하며 MAC Table learning·Unknown Unicast Flooding·VLAN/Trunk·STP는 모델링하지 않습니다. Proxy ARP·Static Route·NAT·동적 라우팅·ICMP Redirect·ICMP Destination Unreachable·ICMP Time Exceeded·ARP cache aging/state transition도 범위 밖입니다. 동일 인터페이스로 다시 forwarding되는 고급 구성에서도 Route/ARP/Frame 전달만 표시합니다.
