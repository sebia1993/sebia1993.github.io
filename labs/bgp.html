01 · 질문과 그림으로 시작

같은 목적지로 가는 두 길 중 더 짧은 길을 항상 써야 할까요?

30초 핵심 · BGP는 네트워크 운영 영역 사이에서 경로와 그 속성을 주고받습니다. 사용할 길을 고르는 것과 이웃에게 어떤 길을 알려줄지는 정책으로 제어할 수 있습니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

AS / eBGP / iBGP
AS는 한 관리 정책 아래 운영하는 라우팅 영역입니다. 다른 AS 사이는 eBGP, 같은 AS 내부는 iBGP 관계입니다.
Path Attribute / AS_PATH
경로에 딸린 정보가 속성입니다. AS_PATH는 경로가 거쳐 온 AS 정보를 나타내며 물리 라우터 수와 같지 않습니다.
LOCAL_PREF
같은 AS 내부에서 어느 출구를 선호할지 나타내는 값입니다. 이 예제에서는 이 값을 높여 선택을 바꿉니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  4. 선택 결과를 반영하고 정책에 따라 이웃에게 경로를 알립니다.

1단계 · CONCEPT GUIDE

BGP / Route Policy

같은 목적지로 갈 수 있는 길이 여러 개라면 어떤 길을 사용할까요? BGP(Border Gateway Protocol)는 네트워크 운영 영역 사이에서 경로 정보를 주고받고, 받은 경로의 정보와 운영 정책을 함께 보고 사용할 길을 고르는 프로토콜입니다.

후보 경로 → 경로에 딸린 정보·정책 → 사용할 길(Best Path) → Routing Table · 광고

전문용어로는 경로에 딸린 정보를 Path Attribute라고 합니다. 핵심은 “길이 존재한다”와 “그 길을 선택한다”, “그 길을 다른 이웃에게 보여준다”를 구분하는 것입니다.

00 · 첫 질문

목적지는 같은데 길이 두 개라면?

경로 A · R2 방향목적지 203.0.113.1/32로 가는 후보
?
경로 B · R3 방향같은 목적지로 가는 또 다른 후보
30초 핵심: BGP는 목적지 Prefix와 함께 경로의 속성(Path Attribute)을 받습니다. 여러 후보가 있으면 정책과 속성을 비교해 하나의 Best Path를 선택합니다.

AS(Autonomous System)는 하나의 관리 정책 아래 운영되는 라우팅 영역을 번호로 식별한 것입니다.

AS 65003

다른 운영 영역

이번 검증에서는 R1↔R2, R1↔R3가 eBGP였습니다.

R1↔R4는 같은 AS65001 내부의 iBGP였습니다. eBGP/iBGP는 케이블 종류가 아니라 AS 관계로 구분합니다.

02 · MENTAL MODEL

BGP의 흐름은 다섯 단계로 기억하세요.

1

Session

Neighbor와 BGP 연결을 맺습니다.

2

Route 수신

목적지 Prefix와 Path Attribute를 받습니다.

3

후보 비교

쓸 수 있는 여러 경로를 비교합니다.

4

Best Path

정책과 속성에 따라 사용할 경로를 고릅니다.

5

반영 · 광고

선택 경로를 Routing Table에 반영하고 정책에 따라 다른 Neighbor에 광고합니다.

03 · PREFIX + ATTRIBUTES

Route는 목적지 주소만 있는 정보가 아닙니다.

표를 읽기 전에: AS_PATH는 경로가 거쳐 온 AS 정보, LOCAL_PREF는 같은 AS 내부에서 어느 출구를 더 선호할지 나타내는 값, NEXT_HOP은 다음에 전달할 Router를 뜻합니다.
BASELINE BEST

R2에서 받은 후보

Prefix203.0.113.1/32
AS_PATH65002
LOCAL_PREF100
NEXT_HOP10.0.12.2
OTHER CANDIDATE

R3에서 받은 후보

Prefix203.0.113.1/32
AS_PATH65003 65003 65003
LOCAL_PREF100
NEXT_HOP10.0.13.2
실제 Baseline: 두 후보 모두 Weight 0, LOCAL_PREF 100, Origin IGP로 통제했고 R2의 AS_PATH가 더 짧았습니다. Cisco IOL에서 R2가 Best Path가 되었고 실제 Ping도 R1-R2 링크에서만 3/3 관측됐습니다.

AS_PATH 문자열을 실제 Router 개수로 읽지 마세요.

이번 R3 경로의 반복된 65003은 실험을 위해 AS_PATH prepend 정책으로 만든 속성입니다. 물리적인 Router가 세 대 더 있다는 뜻이 아닙니다.

04 · ROUTE POLICY

정책은 “어느 길을 더 선호할지” 바꿀 수 있습니다.

BASELINE

R2가 선택됨

R2 · LOCAL_PREF 100 · AS_PATH 65002 → Best
R3 · LOCAL_PREF 100 · AS_PATH 65003 65003 65003
→
POLICY APPLIED

R3 LOCAL_PREF를 200으로 올림

R2 · LOCAL_PREF 100 · AS_PATH 65002
R3 · LOCAL_PREF 200 · 긴 AS_PATH → Best
실제 관측: Cisco IOL의 통제된 조건에서 R3의 LOCAL_PREF를 200으로 높이자 Best/RIB Next Hop이 R2(10.0.12.2)에서 R3(10.0.13.2)로 바뀌었고, marker Ping 3/3도 R1-R3 링크에서만 보였습니다. 정책 제거 후 R2로 복구됐습니다.

이번 페이지는 Cisco Best-Path 전체 순서를 외우는 과정이 아닙니다.

표준 BGP의 핵심은 경로 속성과 정책을 이용해 선택을 제어한다는 점입니다. Cisco의 세부 Best-Path 비교 순서는 구현 Reference로 구분하며, 이번 실험은 선행 조건을 통제한 한 사례입니다.

05 · iBGP PROPAGATION

같은 AS 내부에도 선택 결과와 내부 선호 정보를 전달합니다.

상태R4 AS_PATHLOCAL_PREFNEXT_HOP
Baseline6500210010.0.14.1

STANDARD BEHAVIOR

iBGP라고 AS_PATH에 내 AS가 자동 추가되지는 않습니다.

R4가 받은 경로는 R1이 선택한 외부 AS_PATH를 그대로 반영했고, LOCAL_PREF도 같은 AS 내부에 전달됐습니다.

EXPLICIT IMPLEMENTATION

NEXT_HOP=R1은 next-hop-self 설정 결과입니다.

이번 Lab은 R1→R4에 next-hop-self를 명시했습니다. iBGP 자체가 항상 NEXT_HOP을 자동 변경한다고 일반화하지 않습니다.

06 · ADVERTISEMENT POLICY

Route Policy는 “어떤 경로를 보여줄지”도 제어합니다.

TARGET-ONLY FILTER

광고 허용 범위를 제한

TARGET · 203.0.113.1/32 → 광고
EXTRA · 198.51.100.2/32 → 광고하지 않음
  • R2 자체 BGP Table에는 둘 다 존재
  • R1에는 TARGET만 보임
REMOVE → RECOVER

필터를 제거하면 EXTRA가 나타남

필터 제거 → EXTRA 광고
필터 재적용 → EXTRA Withdrawal
  • TARGET는 계속 유지
  • 최종 상태에서 EXTRA는 다시 사라짐

Prefix Filter ≠ Packet ACL

여기서 Filter는 데이터 패킷을 Drop하는 규칙이 아니라, BGP Neighbor에게 어떤 Route를 광고할지 제어하는 정책입니다.

07 · REVIEW

이 다섯 문장을 설명할 수 있으면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • eBGP/iBGP는 장비 종류가 아니라 AS 관계로 구분합니다.
  • BGP Route는 Prefix와 Path Attribute를 함께 다룹니다.
  • 여러 후보 중 정책과 속성을 비교해 하나의 Best Path를 선택합니다.
  • LOCAL_PREF 같은 정책 값은 같은 AS에서 선호할 Exit를 바꿀 수 있습니다.
  • Prefix Filter는 Packet 차단이 아니라 Route Advertisement 범위를 제어합니다.
