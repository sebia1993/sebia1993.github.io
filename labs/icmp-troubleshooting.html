05 · 1단계 CONCEPT GUIDE

ICMP / Ping / Traceroute

Ping의 왕복 확인과 Traceroute의 중간 경로 확인을 구분합니다.

앞선 학습 · ARP / Default Gateway까지의 개념을 연결합니다.

01 · 질문과 그림으로 시작

응답이 돌아오는지와 어느 장비까지 갔는지는 어떻게 다르게 확인할까요?

30초 핵심 · Ping은 보낸 요청에 대한 응답이 돌아오는지 봅니다. Traceroute는 패킷이 갈 수 있는 범위를 조금씩 늘리며 중간 라우터의 응답을 확인합니다.

02 · 방금 본 그림에 이름 붙이기

이름보다 역할을 먼저 기억하세요.

ICMP / Echo
IP 통신의 상태를 알리는 메시지 체계가 ICMP입니다. Ping은 Echo Request(요청)와 Echo Reply(응답)를 사용합니다.
TTL / Hop
TTL은 패킷이 계속 떠돌지 않게 제한하는 값입니다. 라우터를 한 번 거치는 구간을 Hop(홉)이라고 합니다.
Time Exceeded
TTL이 만료됐음을 알리는 메시지입니다. Traceroute는 이런 중간 응답을 경로 단서로 씁니다.

03 · 동작 순서

핵심 흐름을 연결해 봅니다.

  1. Ping 요청을 보내고 대응하는 응답이 돌아오는지 봅니다.
  2. 경로를 확인할 때는 Traceroute가 작은 TTL로 시험 요청을 보냅니다.
  3. 중간 라우터의 TTL 만료 응답으로 해당 홉을 확인합니다.
  4. TTL을 늘려 다음 홉과 목적지의 응답을 확인합니다.

04 · 헷갈리는 지점

헷갈리는 의미를 구분해서 읽으세요.

구분뜻
Ping 응답 수신해당 시험의 왕복 통신이 됐다는 뜻입니다.
Ping 무응답어디가 왜 막혔는지까지 확정한 것은 아닙니다. 경로와 응답 메시지를 함께 봅니다.

05 · 복습

꼭 기억할 세 가지

  • Ping은 왕복 응답을 확인합니다.
  • Traceroute는 TTL을 바꿔 중간 경로를 확인합니다.
  • 무응답 하나로 장애 원인을 단정하지 않습니다.

1단계 · CONCEPT GUIDE

ICMP / Ping / Traceroute

목표는 하나입니다. Ping과 Traceroute 결과를 ICMP 메시지와 TTL 변화에 연결해, 어디까지 통신됐고 왜 멈췄는지 설명할 수 있으면 됩니다.

이 페이지에서는 원리만 이해합니다.명령 출력이나 PCAP 원문을 외우지 않습니다. 핵심 흐름을 만든 뒤 2단계에서 직접 움직여 확인합니다.
1 · 개념서2 · Interactive Lab
Ping은 “응답이 돌아오는가”, Traceroute는 “어디까지 갔는가”를 봅니다.

Echo Reply · TTL · Time Exceeded · Destination Unreachable

00 · 30초 핵심

실패 문구보다 ICMP 메시지를 먼저 봅니다.

① Ping: Echo Request를 보내고 대응하는 Echo Reply가 돌아오면 왕복 도달을 확인할 수 있습니다.

② Router: IPv4 Packet을 전달할 때 TTL을 줄입니다.

③ Traceroute: TTL을 일부러 작게 보내 Time Exceeded를 발생시키며 중간 Hop을 드러냅니다.

④ 실패: Destination Unreachable을 받았다면 누가 어떤 Code를 보냈는지와 Route 상태를 함께 봅니다.

01 · PING

Ping의 핵심은 Request와 Reply 한 쌍입니다.

화면의 성공 문구는 이 왕복 결과를 요약한 것입니다.

R1 · SourceEcho Request 전송
→ Type 8 · Echo Request
← Type 0 · Echo Reply
R3 · DestinationRequest를 받고 Reply 반환
대응 관계: Echo Reply의 Identifier와 Sequence는 요청과 대응합니다. 따라서 여러 Ping 중 어느 Reply가 어느 Request에 대한 것인지 연결할 수 있습니다.
02 · TTL

Router를 지날 때 TTL은 줄어듭니다.

숫자 자체보다 “홉마다 감소한다”는 관계가 중요합니다.

R1TTL = N
→R2로 전달
R2Forwarding
→TTL = N-1
R3목적지
TTL이 0이 되면? Router는 그 Packet을 다음 Hop으로 보내지 않고 폐기한 뒤 Source에 ICMP Time Exceeded · Type 11 Code 0을 돌려보냅니다.
03 · TRACEROUTE

TTL 만료를 일부러 만들어 Hop을 찾습니다.

1

TTL = 1

첫 Probe가 R2에서 만료됩니다.

2

R2 → Time Exceeded

R1은 “첫 번째 Hop은 R2”라고 알 수 있습니다.

3

TTL = 2

다음 Probe는 R3까지 도달합니다.

4

Destination 응답

Cisco IOS UDP traceroute에서는 R3의 Port Unreachable로 도달을 확인할 수 있습니다.

구현 차이: “Traceroute는 항상 UDP”는 아닙니다. 이번 Cisco IOS 검증은 UDP Probe를 사용했지만 Windows tracert는 ICMP Echo Probe를 사용합니다. 공통 핵심은 TTL을 단계적으로 바꾸며 중간 응답으로 Hop을 확인한다는 점입니다.
04 · DESTINATION UNREACHABLE

“도달 불가”도 이유를 나눠 봅니다.

Type 3의 Code와 Route 상태를 함께 해석합니다.

RFC 표준

Code 0 · Network Unreachable

RFC 1812는 Router에 목적지로 가는 Route가 전혀 없을 때 Network Unreachable을 요구합니다.

Cisco 구현 관찰

Code 1 · Host Unreachable

이번 Cisco IOS Lab과 Cisco 공식 문서에서는 “목적지 Route를 모름” 상황에서도 Host Unreachable이 관찰·기술됩니다.

운영에서 중요한 결론: Code 하나만 보고 원인을 확정하지 않습니다. 누가 ICMP를 보냈는지 + 그 Router의 Routing Table + 다음 링크에 Packet이 나갔는지를 함께 봅니다.
05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Ping은 Echo Request ↔ Echo Reply 왕복을 확인합니다.
  • Router는 IPv4 Packet을 Forward할 때 TTL을 감소시킵니다.
  • TTL이 만료되면 Time Exceeded가 경로 단서를 줍니다.
  • Traceroute는 TTL을 바꾸며 Hop을 단계적으로 확인합니다.
  • Ping 실패는 원인이 아닙니다. ICMP 응답과 Route 상태를 함께 봅니다.
