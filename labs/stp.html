1단계 · CONCEPT GUIDE

STP / RSTP

목표는 하나입니다. Redundant Triangle에서 Root와 Port Role이 어떻게 Loop-Free Tree를 만들고, 장애나 Cost/Root 변화 때 경로가 어떻게 다시 계산되는지 설명할 수 있으면 됩니다.

물리 Link와 논리 Forwarding Path를 분리해서 봅니다.Cable이 Up이라고 해서 모든 Link가 User Data를 Forward하는 것은 아닙니다.
1 · 개념서2 · Interactive Lab
Root를 정하고 → 가장 좋은 길을 남기고 → 나머지 길을 대기시키고 → 장애 때 다시 계산합니다.

BPDU · Root Bridge · Root/Designated/Alternate · Cost · Rapid Convergence

00 · 30초 핵심

STP는 Link를 없애는 것이 아니라 Forwarding Tree를 하나만 남깁니다.

① Root: BPDU를 비교해 가장 우수한 Bridge ID를 가진 Switch가 Root가 됩니다.

② Root Port: Non-root Switch는 Root까지 가장 낮은 누적 Cost 경로를 고릅니다.

③ Alternate: Redundant Port는 Cable Up 상태로 남을 수 있지만 User Data Forwarding에서는 제외됩니다.

④ RSTP: Link나 Root가 바뀌면 Role을 다시 계산해 Standby Path를 Forwarding으로 전환합니다.

01 · ROOT BRIDGE

Priority가 먼저, MAC은 Tie-break입니다.

Equal Priority

32768 / 32768 / 32768

이번 Lab에서는 SW1 MAC이 가장 낮아서 SW1이 Root로 예측됐고 실제 BPDU/CLI도 일치했습니다.

Deterministic Baseline

SW1 24576 · SW2 28672 · SW3 32768

Priority 차이를 주면 MAC Tie-break보다 Priority가 먼저 적용되어 SW1 Root가 유지됐습니다.

표시 숫자 주의: Cisco CLI의 VLAN10 Operational Priority는 Extended System ID 때문에 Base Priority에 VLAN10 값이 더해져 24586처럼 보였습니다. Configured Base Priority와 화면 숫자를 그대로 동일시하지 않습니다.
02 · PORT ROLE

Triangle을 하나의 Loop-Free Tree로 바꿉니다.

Root Port

Root로 가는 최적 경로

Non-root Switch마다 하나를 선택합니다. Root Bridge에는 Root Port가 없습니다.

Designated Port

Segment의 Forwarding 대표

각 Segment에서 가장 좋은 BPDU를 제공하는 쪽이 Designated 역할을 맡습니다.

Alternate / Discarding

대기 경로

User Data는 Forward하지 않지만 BPDU Control Plane에는 참여하는 Standby Path입니다.

이번 Baseline: SW1이 Root, SW3→SW1(L31)이 Root/FWD, SW3→SW2(L23)가 Alternate/BLK였습니다. PC1→PC3 실제 Data Path는 PC1 → SW1 → L31 → SW3 → PC3였습니다.
03 · TOPOLOGY CHANGE

물리 Triangle은 그대로, 역할과 실제 Path만 바뀝니다.

PATH COST

SW3→SW1 Cost 4 → 20

Direct Path 20보다 SW3→SW2→SW1 누적 Cost 8이 더 낮아져 SW3 Root Port가 L23으로 바뀌었습니다.

LINK FAILURE

SW3→SW1 Root Port Link Down

L23이 Root/FWD로 전환됐고 100개 연속 Probe는 100/100 Reply였습니다. 실제 Data Path 전환 Delivery Gap은 약 0.202초였지만, 이는 200ms Probe 기반 관찰값이지 보편적 RSTP 수렴 시간은 아닙니다.

ROOT CHANGE

SW3 Priority → 16384

Root가 SW3로 바뀌며 차단 위치도 이동했습니다. Baseline의 SW3-L23 Alternate 대신 SW2-L12가 Alternate/BLK가 됐습니다.

04 · RSTP FLOW

장애 때도 “Loop-Free Tree” 원칙은 그대로입니다.

1

BPDU 비교

Root와 각 Port의 Best Path 정보를 계속 교환합니다.

2

Role 선택

Root / Designated / Alternate 역할을 정합니다.

3

Data Forwarding

Forwarding Tree에 포함된 Link만 User Data Path가 됩니다.

4

Topology Change

Link/Cost/Root 변화가 생기면 Role을 다시 계산합니다.

5

Standby 활성화

Alternate가 새 Root Path로 승격되어 연결성을 유지할 수 있습니다.

05 · REVIEW

여기까지만 기억하면 1단계 완료입니다.

⭐ 꼭 기억하세요

  • Root 선출은 Bridge ID 비교이며 Priority가 먼저입니다.
  • Non-root Switch의 Root Port는 Root까지 가장 좋은 Path입니다.
  • Alternate/Discarding은 Cable Down이 아니라 논리적 Standby입니다.
  • Path Cost가 달라지면 Root Port와 실제 Data Path도 바뀔 수 있습니다.
  • RSTP는 장애 후에도 Loop-Free Tree를 다시 구성합니다.
내 말로 설명하기

“왜 Triangle의 세 Link가 모두 Up인데 User Data는 한 Tree로만 흐르는가?”

Root Bridge, Root Port, Alternate/Discarding, Cost라는 네 단어를 사용해 설명할 수 있다면 충분합니다.
